# KD163 本地服（口袋修仙 / 梦幻神界）

自建游戏服务端的协议重实现。目标是把线上服完整搬到本地：真账号登录 → 建角 → 场景 → 任务 →
战斗 → 背包/装备/强化 → 宠物/妖灵 → 称号/VIP/商城，全链路按真服抓包逐字节对齐，不靠假登录、
不靠默认角色、不靠客户端骗包。

> 服务端是纯 Python，无第三方依赖（仅标准库 + 本地 `res_cfg/` 配置表）。

## 一、跑起来

```bash
# 1) 启动游戏服（证书已随仓库提供：patch/exact.pem + patch/exact.key）
python local_server3.py 9000 patch/exact.pem patch/exact.key

# 2) 启动资源服（端口 80，客户端拉资源/版本清单用；第二个参数是宿主机的局域网 IP）
python local_http.py 80 192.168.0.111
```

```bash
# 3) 客户端侧（模拟器 / 真机）
adb reverse tcp:9000 tcp:9000     # 游戏协议（TLS /auth + 明文游戏包，同一个口）
adb reverse tcp:8080 tcp:80       # 资源 CDN（注意是 8080→80，不是 8080→8080）
```

进游戏后用任意账号密码登录。**账号第一次登录会走「无角色 → 建角」流程**：
客户端会弹建角界面（男/女 + 昵称 + 创建），创建完直接是干净的 Lv1 未转职号，
身边没有熊猫、背包空、钱 0 —— 这是设计行为，不是缺数据。

> 仓库里**不带玩家存档**（`player_state*.json` 全在 .gitignore 里），所以 clone 下来第一次
> 登录一定是新号。想跳过建角，可以写 GM：`printf '建角 小林 男\n' > logs/gm.cmd`（主号），
> 或 `printf '@账号 建角 小林 男\n' > logs/gm.cmd`（指定账号）。

网页后台（可选）：

```bash
python admin_server.py            # 默认 8081，读写 logs/gm.cmd
```

## 二、仓库里没有、但你必须自备的东西

**下面三样缺一不可，缺哪样就卡在哪一步：**

| 缺什么 | 表现 | 说明 |
|---|---|---|
| **客户端 APK** `patch/kd163_coexist.apk`（119MB） | 登录界面一直转圈 / 「网络连接失败」 | 改过包的版本：包名 `com.kdxx.local1`（可与原版共存），`classes.dex` 内嵌信任根 + 用 `exact.pem` 签名。**原版 APK 连不上**——它只信任官方 CA，握手直接失败 |
| **资源包** `res_update/mhsj_res.zip`（109MB，md5 `5efc42ed36978e860f135a96bd93c85a`） | 能登录，但进主城/切图时 native abort 或一直卡加载 | 必须与抓包同版本。APK 内置资源包比服务端版本旧，拿它顶替会在进主城时崩 |
| **`exact.pem` + `exact.key`** | TLS 握手被拒 | **已随仓库提供**（`.gitattributes` 锁了行尾，clone 后字节不变），md5 `126de9578e43df3c3278583cf09c5504`，必须与 APK 内嵌/签名的那张是同一张 |

两个大文件都超过 GitHub 单文件 100MB 上限，只能网盘/直传，不要塞进仓库。

如果对方想用**自己生成**的证书，就必须同时重打包 APK：

```bash
python gen_cert_exact.py          # 生成新的 exact.pem / exact.key
python patch_coexist.py           # 把新公钥内嵌进 APK 并重新签名（包名等长替换）
```

只换服务端证书、不重打包 APK → 客户端 TLS 握手被拒，表现为登录界面一直转圈或「网络连接失败」。

其余自备项：

| 文件 | 说明 | 怎么拿 |
|---|---|---|
| `tools/` | adb、scrcpy 等（820MB） | 自行安装；只需要 adb，能 `adb reverse` 就行 |
| `res_x/`、`srvres/` | 资源解包产物（126MB×2） | 只有想自己重新打资源包/查 UI 布局时才需要；**平时跑服不需要** |

**随仓库提供的**：`res_cfg/`（4.3MB 配置表）、`mirror/`（3.9MB，含 `assets/configure/*.xml`、
`meta.xml`、`server-list.xml`、`assets.txt`）、`logs/`（14.6MB 真服/他服抓包，分析用）。
服务端和资源服启动时直接读这些，不需要额外解包。

## 四、协议要点（踩过的坑，改代码前先看）

- 帧格式：`pack(cmd, seq, payload) = >HHI(len) + cmd + seq + payload`，`len` 含 6 字节头。
- 变长整数 `enc_val`：`<0x80` 单字节 / `0x80~0xFF` 用 `cc` / `0x100~0xFFFF` 用 `cd` / 更大用 `ce`。
  **分档写错会让客户端收到 151 后干净退出**（打怪闪退的真凶）。
- 未注册的 cmd **必须静默丢弃**，绝不能回 `cmd=1` —— 实测 30ms 内 SIGABRT。
- `cmd=4` 心跳、`cmd=115` 移动：115 需要回两条 `118`（`06<pos>` / `10<pos>`），否则寻路走两步就停。
- `145` 开战 → 回 `145` 空 ACK + `151`；`146` 回合 → `148`；`149` → `150` 结算。
- 客户端每回合固定扣 **16**（打怪）/ **13**（挨打）点血，血条与服务端回合必须按这个折算，否则
  「怪血还满着就弹胜利」。见 `battle.py` 的 `max_hp` / `disp_player_hp_max`。
- 登录三包 `17 / 28 / 30` 的 `(性别, 职业, 等级)`、经验、装备必须同源，否则等级乱跳甚至渲染段错误。

### 干净 clone 验收（2026-11-24 实测）

在一份全新 `git clone` 上跑过完整链路，结论是**服务端侧零配置可跑**：

| 步骤 | 结果 |
|---|---|
| 启动 | `python local_server3.py 9100 patch/exact.pem patch/exact.key` 正常监听 |
| 证书 | clone 后 `patch/exact.pem` md5 = `126de9578e43df3c3278583cf09c5504`，与源目录一致 |
| TLS `/auth` | `HTTP=200`，日志 `TLS 证书已加载：patch/exact.pem` → `放行 uid=...` |
| 新账号登录 | 回 `cmd=1 01a0`（无角色），**客户端弹出建角界面**（男/女 + 昵称） |
| 建角 | `cmd=20` → 157B 应答 + 113/117 → 进开场剧情 → 蓬莱仙境 Lv1 未转职 |
| 开始旅程 | `182` → 空 ACK + 29/28/178，九天玄女对话弹出，任务 400101 可接 |
| 接任务 | `211` → 7B 应答，任务直接置「可交」 |
| 交任务 | `214` → 升级 Lv1→Lv4、推 29/28/88/210，自动接下一环 400201 |
| 战斗 | `145` → 145 ACK + 151 → `146` → 148 → `149` → 150，攻/防两端都验过 |

**这次验收的边界（别误读）**：客户端用的仍是本机已配好的改包 APK 和资源包，
`adb reverse tcp:8080 tcp:80` 指向的是**主目录**的 `local_http.py`。
也就是说——**服务端和配置表 clone 下来就能跑；客户端和资源包仍要单独拿**（见第二节）。
换一台完全空的机器，按第二节把三样补齐后是同一套流程。
