# 路线 A：零改客户端接管服务端（2026-11-22 实测通过）

## 结论

不改 APK、不动 dex、不去证书固定，用 **iptables DNAT + 本机双服务**，让原版客户端连上自建服务端，
**已进主城、UI 面板可正常打开、心跳持续 10 秒一次不断连**。

L2（进主城）从"卡在资源崩溃"变成"已打通"。

---

## 架构

```
模拟器内客户端
   │  访问 124.223.56.189:80 / :9000
   ▼
[iptables -t nat OUTPUT DNAT]
   ├── :80   → 192.168.0.111:80    local_http.py   （静态端点）
   └── :9000 → 192.168.0.111:9000  legacy/local_server2.py（游戏协议）
                                      ├─ 首字节 0x16（TLS）→ 透传真服 /auth
                                      └─ 明文 → 按真服单向序列回放
```

- **登录仍走真服**：`/auth` 是 TLS + 证书固定，客户端只认 dex 里那张自签证书，
  没私钥就无法本地应答 → 透传给 `124.223.56.189:9000` 校验。
- **游戏协议完全本地**：登录令牌之后的全部 TCP 交互由本机应答。

## 配置（可复现）

```bash
# 1) 起两个服务
python local_http.py 80 192.168.0.111
python legacy/local_server2.py 9000

# 2) 模拟器内改向（需 root）
su 0 sh -c '
  iptables -t nat -F OUTPUT
  iptables -t nat -A OUTPUT -d 124.223.56.189 -p tcp --dport 80   -j DNAT --to-destination 192.168.0.111:80
  iptables -t nat -A OUTPUT -d 124.223.56.189 -p tcp --dport 9000 -j DNAT --to-destination 192.168.0.111:9000
'

# 3) 恢复真服
su 0 iptables -t nat -F OUTPUT
```

真服 IP 不能写错、宿主机 IP 不能用 `172.16.1.1`（那是虚拟网关，宿主机上没有该地址，
表现为 DNAT 计数上涨但服务收不到连接）。

## 三个把进度卡住的坑（重点）

### 坑 1：`c033_game.bin` 是**双向混流**，不是单向

`c033_game.bin` 是抓包代理把收发两个方向按抓取顺序写进同一个文件的结果。
按 `[len][cmd][seq]` 硬切能切出 106 个"合法"包，但里面混着 C→S 和 S→C。
第一版直接把它当 S→C 回放，等于**把客户端自己的请求原样回给了客户端** →
客户端收到 `cmd=17 len=58`（它自己刚发的登录包）立刻崩。

**正确来源**：`capture/c033_game.log` 带 `C->S / S->C` 方向标记，取其中 S->C 段，
按出现顺序得到 42 个包（含 15 个 `seq=0` 的主动推送）。

### 坑 2：响应不止一条，不能"遇到第一条同 seq 就停"

登录 `seq=2` 时真服连发两条：`cmd=17 len=58`（应答外壳）+ `cmd=17 len=152`（角色数据）。
暂停在第一条会漏掉角色数据，客户端立刻断连。

**修法**：客户端发来 `seq=S` 后，在回放序列里向前找第一条 `seq==S` 的包，
把指针到该位置之间的**所有包**（含推送）一次发出，再推进指针。

### 坑 3：漏发 `seq=0` 的主动推送 → native 层 SIGABRT

真服在登录后立刻推 `cmd=113`(34B 场景/玩家列表)、`cmd=117`、`cmd=178` 等 15 个推送。
只回"请求的响应"时，客户端拿不到场景信息，随后调用
`JniHelp_nativeGetFileOffsetAndSize` 去查一个空名字的资源偏移，
native 层直接 abort（logcat: `enter nativeGetFileOffsetAndSize` → 63ms 后进程死亡，无 tombstone）。

**修法**：按真服原顺序连推送一起回放，问题消失。

## 还没解决 / 下一步

1. **登录仍依赖真服**（证书固定）。要彻底独立必须改 dex 去 pin，属路线 B。
2. **人物不一定是"你自己的角色"**：登录响应是抓包时的快照（萌新/lv71），
   要支持多账号得自己实现角色数据结构。
3. **玩法操作没有语义**：走路、打怪、接任务的请求目前靠模板/空包应付，
   客户端点下去不一定有反应。要补 cmd 语义表。
4. **DNAT 期间客户端只能连本机服务**，要玩真服必须先 `iptables -t nat -F OUTPUT`。
