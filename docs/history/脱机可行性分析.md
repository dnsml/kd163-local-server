# kd163.apk 脱机可行性分析

> 分析对象：`F:\QQNT\kd163.apk.1`（124MB）
> 分析时间：2026-11-22
> 方法：纯静态解析（dex 字节码 / ELF 符号 / 字符串）+ 服务端实测

---

## 一、这个包的真实身份

不是官方包，是**别人在运营的线上服客户端**，而且改动相当专业。

| 项目 | 值 | 说明 |
|---|---|---|
| 包名 | `com.kdxx.online` | 壳层，与官方 `com.aiyou.mhsj` 无关 |
| 版本 | `2.2.1-online-r149-bluestacks` | 模拟器渠道改包 |
| 游戏内核 | `libgame.so` 8.8MB | cocos2d-x，armeabi + armeabi-v7a |
| 资源包 | `assets/mhsj_res.zip` 110MB | 6251 项，全是素材和配置表，无脚本 |
| 壳层 SDK | `com.aiyou.sdk.Impl_Local` / `Impl_4399sy` | 双登录实现 |

关键判断依据：`Impl_Local.java` 里内嵌了一张自签证书，并且做了**证书固定**（certificate pinning）——这是自建服务端才需要的东西，官方 SDK 不会这么写。

## 二、现有服：能玩，但门槛在账号

### 实测结果（2026-11-22 10:30）

```
POST https://124.223.56.189:9000/auth
Content-Type: application/json; charset=utf-8
{"username":"...","password":"..."}

→ 400 {"ok":false,"error":"账号需为1到32位英文字母、数字、下划线或横线"}
→ 401 {"ok":false,"error":"账号或密码错误"}
→ 200 {"ok":true,"token":"<43位base64url>","account_id":"..."}
```

服务器列表：

```
GET http://124.223.56.189/server-list.xml
→ <item id="1" name="口袋修仙正式服" ip="124.223.56.189" port="9000" if_recommend="1" condition="1"/>
```

### 网络层结构

| 项目 | 结果 |
|---|---|
| 9000 端口 | TLS 1.3 握手可成功（HTTP API 用），**但游戏协议是裸 TCP** |
| 证书 | 自签，CN=124.223.56.189，有效期 2026-11-14 → 2036-11-11 |
| 443 端口 | 不通 |
| 明文 TCP 探测 | `GET /`、空包、全零包均无响应（格式不对，被丢弃而非拒绝） |
| 注册接口 | `/register` `/signup` `/api/register` 等 7 个常见路径全 404 |

**结论**：账号只能由服主开通，客户端里没有注册入口。

## 三、脱机的真实门槛

### 3.1 客户端内没有任何离线分支

对 `libgame.so` 全文检索 `offline` / `single player` / `standalone` / `no network`：**0 命中**。

游戏链路是硬连线：

```
PreLoginScene → Login → SelectServer(ServerItem/ZoneItem) → TLS(9000) → cmd/seq RPC → 场景
```

`NetworkHandler` 里有 `unordered_map<uint, PendingCall>`，这是标准请求-响应 RPC（每个请求带 uint 序号等回调）。**所有状态在服务端**：角色、背包、任务、战斗结算、帮派、活动排行。

### 3.2 三道硬卡点

| 卡点 | 说明 | 解析难度 |
|---|---|---|
| ① 证书固定 | 客户端只信任 dex 里那张自签证书，本地服务端没有对应私钥 | **必须改客户端** |
| ② 游戏协议 | **明文 TCP，不是 TLS**（见下方修正） | 抓包重放即可，不需要额外的动态调试框架 |
| ③ 服务端逻辑 | 数百个 cmd 的业务逻辑要逐个实现 | 人月级 |

#### 修正：游戏协议是明文 TCP

对 `libgame.so` 的导入符号做全量枚举，结果是：

```
socket  connect  send  sendto  recv  recvfrom  close  select  poll  getaddrinfo
```

**没有任何 `SSL_*` 符号。** 也就是说 cocos2d-x 内核用的是裸 BSD socket，
TLS 只用在 Java 层的 `/auth` 接口（`HttpsURLConnection`）。

9000 端口应该是靠首字节分流：`0x16` 走 TLS（HTTP API），其他走游戏协议。
这解释了为什么 TLS 握手能成功、但发 `GET /` 没有响应——那是被当成游戏包丢掉了。

**这条把脱机难度降了一大截**：不需要 root + 运行时抓点，抓包就能拿到明文协议。

### 3.3 工作量分层

| 层级 | 目标 | 需要做什么 | 估时 |
|---|---|---|---|
| **L1** | 本地假服过登录 | 改 dex 去证书固定 + 改 AUTH_URL + 起本地 HTTPS 返回 token | 1 天 |
| **L2** | 过选服、握手 | 伪造 server-list + 实现第一个 TCP 包 | 3–5 天 |
| **L3** | 进场景能看角色 | 运行时抓点 抓明文 + 协议分析进场协议族（几十个 cmd） | 2–4 周 |
| **L4** | 能走能打能捡 | 战斗、背包、任务、地图同步 | 2–6 个月 |

**L3 之后才是"能玩"，L1–L2 只能看到空壳界面。**

## 四、技术资产清单（已确认可用）

### JNI 桥（libgame.so 导出）

```
Java_com_aiyou_mhsj_JniHelp_nativeSetServerListURL   ← 服务器列表 URL 由 Java 传入
Java_com_aiyou_mhsj_JniHelp_nativeSetServerId
Java_com_aiyou_mhsj_JniHelp_nativeLoginSucceed1/2/3/4 ← 登录成功后把凭据交给内核
Java_com_aiyou_mhsj_JniHelp_nativeInitPackage
Java_com_aiyou_mhsj_JniHelp_nativeSetExternalResourcePath
```

### 登录调用链（dex 还原）

```
Impl_Local.showLogin()          弹账号密码框
  → submit()                    校验 [A-Za-z0-9_-]{1,32}
  → authenticate()              POST /auth，自定义 TrustManager 校验证书
  → complete()                  Handler 回调
  → finishAttempt()             → JniHelp.nativeLoginSucceed2(...) 进入游戏
```

`nativeLoginSucceed1/3/4` 在 `Impl_Local` 路径下**未被调用**，属于官方 SDK 通道。

### 服务端地址的配置点

`libgame.so` 里**没有硬编码任何 IP**。服务器地址完全由 Java 层通过 `nativeSetServerListURL` 传入，运行时再拉 `server-list.xml`。

→ 这意味着改地址只需改 dex 一处，不用碰 so。

## 五、结论

1. **现有服**：能连、能玩，但需要找服主要账号（无自助注册）。
2. **脱机**：技术上可做，但"能玩"要 2–6 个月。L1–L2 一周内可交付，只是空壳。
3. **最优切入**：先抓明文协议（运行时抓点），量化 cmd 数量，再决定做到哪一层。

## 六、有账号之后能做什么（无需模拟器）

拿到可用账号后，以下步骤本机就能跑，不需要安卓设备和额外的调试框架：

| 步骤 | 做法 | 产出 |
|---|---|---|
| 1 | `POST /auth` 拿 token，验证账号有效性 | 确认能进服 |
| 2 | 裸 TCP 连 9000，按各种长度前缀/头格式试探 | 摸出包结构 |
| 3 | 用 token 构造首个包，观察服务端响应 | 确认握手字段 |
| 4 | 对照 `libgame.so` 指令解析校准字段顺序 | 协议文档 v1 |

之后才是"改客户端指向本地"和"写服务端"。

### 还需要的东西

| 事项 | 状态 |
|---|---|
