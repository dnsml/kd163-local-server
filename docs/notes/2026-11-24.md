## 02:1x 锁妖塔「进不了下一层」+ 老号回下线点

**1. 下一层不动的根因：跳点 id 和场景 id 数值撞车**

`Scene.xml` 的 `jump_points` 存的是 **Jumppoint id**，不是场景 id：

```
Scene 21201 jump_points="21201,35,5"                 → Jump 21201 → scene 21202
Scene 21202 jump_points="21202,1,5;21203,35,5"       → 21202 回一层 / 21203 去三层
```

真服 relay.log 23:44:06 的整段链把这件事钉死了：

```
C->S cmd=128 hex=cd52d1      ← 客户端发的是一层的跳点 21201
S->C cmd=129 hex=cd52d20305  ← 服务端回的目标场景是 21202，落点 (3,5)
C->S cmd=32513 hex=cd52d2ccdd00
```

上一版代码里有一段「scene_type=3 就直接把 jid 当目标场景」，本意是照顾
「客户端直接发场景 id」的情况，但 `21201` 同时是跳点 id 和场景 id，
于是 `tgt` 被覆盖回 `21201` —— 点下一层等于原地重进一层。日志里两秒钟内
连点两次都是 `21201 -> 21201`：


改法：**Jumppoint 表优先**，只有查不到目标时才退回「jid 即场景」。
