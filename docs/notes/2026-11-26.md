## 6. 30 包尾部块长写错（腰带 / 护腕 / 护符显示空）+ 背包 60 格上限

### 6.1 症状

服务端 `30` 说已穿 9 件，客户端腰带、护腕、护符三格却是空的；背包里的东西也「有件数、看不到」。

### 6.2 30 尾部块长（真正的根因）

真服固定尾部 = 第 12 块 4B + 翅膀块 **20B** + 坐骑块 **6B**，长度与「有没有翅膀/坐骑」无关。
本地旧实现写成「翅膀空 4B / 有 8B，额外 12B，坐骑 4B」，于是：

| 情形 | 旧实现 | 真服 | 后果 |
|---|---|---|---|
| 11 件全满 | 90B | 96B | 客户端从翅膀块开始错位解析，腰带/护腕/护符读成空 |
| 11 件全空 | 68B | 74B | 同上 |

修法（`build_30()`）：

```python
out += _enc30(_wing) + b"\x00" * 15 if wing else b"\x00" * 20   # 翅膀固定 20B
out += b"\xcd" + iid + b"\x0d\x01\x01" if mount else b"\x00" * 6 # 坐骑固定 6B
```

`work/test_acc_equip.py` 长度断言同步 +6B：第一枚戒指 90B、第二枚 92B、满配 96B、
819 卸戒指 94B、卸护符 92B、37 卸槽 1 90B。

## 7. 登录后面板属性显示成「没穿装备」（13:00 修复并实测通过）

### 7.1 现象
重登后四首饰、武器都在（`17` 里装备齐全），但角色面板显示
气血 1271 / 攻击 151-185，穿脱一次任意装备才恢复正常。

### 7.2 根因
登录回放序列里**没有 `29`**（动态属性面板）。客户端只能拿 `17` 的基础值自己算，
而 `42`（打开角色面板）回的真服原包 `43` 里带的是旧属性块，会把面板再刷回基础值。

### 7.3 修法
`cmd=42` 的回包顺序固定为 **`818 → 43 → 29 → 30`**，`43` 之后必须补一条动态 `29`：

```python
_b29role = build_29()
if _b29role:
    conn.sendall(pack(29, 0, _b29role))
_b30role = build_30()
```

实测日志：

```
c002 -> cmd=818 seq=0 len=850 [42 触发 完整装备 真服原包]
c002 -> cmd=43  seq=39 len=345 [角色详情 真服原包]
c002 -> cmd=29  seq=0  len=38  [角色面板补推属性 Lv52]
c002 -> cmd=30  seq=0  len=96  [角色面板补推装备 11件]
```

面板随即恢复：战力 2987 / 气血 3626 / 攻击 376-416 / 防御 168，11 格全在。

### 7.4 注意：登录尾部那份 29/30 补推走不到
它挂在 `if ptr >= len(SEQ) and not quest_pushed:` 里，本次登录 `ptr` 没走到末尾
（客户端中途发 `42` 就走了另一条分支），所以只有 `42` 那条真正生效。
面板刷新靠 `42` 已足够；如果以后要修 HUD 顶栏，得把 29 补在 `17` 应答之后。

## 9. 网络：DNAT 命中计数 + 防误连兜底

`iptables -t nat -L OUTPUT -v -n` 的 pkts 计数可以直接证明规则命中
（实测 `:80` 16 次、`:9000` 1 次）。filter 表新增 `KD_GUARD`：

```
-A KD_GUARD -d 124.223.56.189 -p tcp --dport 9000  -j REJECT --reject-with tcp-reset
-A KD_GUARD -d 124.223.56.189 -p tcp --dport 19000 -j REJECT --reject-with tcp-reset
```

filter OUTPUT 在 nat DNAT 之后评估，正常流量目的地址已被改成 127.0.0.1，
不会撞到；只有 DNAT 丢了才会 RST —— 把「静默登进线上服」变成「明显连不上」。

## 11. 重启客户端后「武器在、饰品全空」，脱一次武器才出现（13:22 修复）

### 11.1 复现路径
重启客户端 → 登录 → 进游戏：饰品 4 格 + 鞋子是空的，武器能看见。
手动脱下武器（触发 `37`）后，`37` 回包里的 `30` 把饰品补了出来。

### 11.2 真因
「登录后补推 29/30」那段挂在

```python
if ptr >= len(SEQ) and not quest_pushed:
```

只有**回放序列全部跑完**才会执行。实测 13:09:46 那次登录，客户端发完 `1265`
就只发 `cmd=4` 心跳（既不发 `42`，也不再要新 seq），`ptr` 永远到不了末尾，
于是 29/30 一条都没补 —— 客户端只拿 `17` 画了武器（外观块里有），
首饰/鞋子没有数据源，就是空格。

### 11.3 修法
改挂在 `cmd == 1265`（客户端初始化最后一步）之后，一次性补 `29 + 30`：

```python
if not equip_pushed[0] and cur().has_char:
    _b29 = build_29(); conn.sendall(pack(29, 0, _b29))
    _b30 = build_30(); conn.sendall(pack(30, 0, _b30))
    equip_pushed[0] = True
```

`equip_pushed` 与 `login_pushed` 同生命周期（每条连接一个 `[False]`）。
`42` 分支补推完也置 `True`，避免重复。

c004 .. push cmd=29 len=38 [登录补推属性 Lv52 生命3626 攻376-416]

## 12. 「绑定铜币-2202471 / 元宝-1749 / 绑定元宝-4050」是怎么回事

不是服务端扣钱，也不是存档丢钱。核对结果：

- `player_state_900000102.json` 里 `coin=101529`，`bind_yuanbao=0`，
  `tongqian=0`，`yuanbao=0`；服务端日志里历次 `28` 只有 101529/107529/110529/116529，
  **从来没有 230 万**。
- 2202471 + 101529 = 2304000：客户端本地缓存着旧会话的 2,304,000，
  收到真实 101,529 时按差额弹了负数飘字。

那 230 万来自**早期第 28 包只覆盖 u32 低 16 位**的 bug（`0x0023xxxx + 低16位`，
`build_28` 注释里记着「会出现 2305802 这种鬼数字」）。该 bug 早已修掉，
这次只是客户端缓存第一次和真实值对账。对账一次后缓存就等于真实值，不会再弹。

背包底栏实测也是 `0 / 0 / 0 / 101529`，与存档一致。

## 15. 13:41 建角覆盖事故 + 三件套/神装槽位修复（13:5x）

### 事故：账号 1784366 的 Lv45 角色被误建角冲掉

`create_character()` 无条件 `reset_newbie()` + `save_state(force=True)`，

### 为什么没备份：`backup_state()` 前缀匹配串号

## 16. 面板 11 格全空（14:0x）—— 30 包尾部多写了 6B

### 现象
角色面板：模型穿着整套御剑装（外观走 `17`），但 11 个装备格**全空**，
只显示「上衣/腰带/…/武器」的灰底文字。

### 根因：30 包长度 88B，真服是 82B
真服 `relay.log` 15:39:25（400501 交完发神装那一串）的 30 原包，逐块解析：

```
off  0 BLOCK6 cd2b64010101   slot1 11108
off  6 BLOCK6 cd2b65020101   slot2
off 12 BLOCK6 cd2b66030101   slot3
off 18 BLOCK6 cd2b67040101   slot4
off 24 BLOCK6 cd2b68050101   slot5
off 30 BLOCK6 cd2b69060101   slot6
off 34 ZERORUN 16B           首饰 4 个空槽（4B×4）
off 50 BLOCK6 cd2b6a070101   武器，第三字节 07
off 56 ZERORUN 24B           4B + 翅膀 20B（无坐骑 → 坐骑块整块不存在）
                             总长 82B
```

本地以前无条件再补 6B 空坐骑 → **88B**。客户端按尾部固定块长解析对不上，
**整包丢弃** → 面板所有格子都是空的。之前记的「坐骑块没坐骑也占 6B」是错的：
那条来自 96B 样本（11 实槽 66 + 4 + 20 + 6），那个号**真有坐骑**（`cd2733000000`）。

### 修复
- `build_30()`：`_mount` 为 0 时**不再写 6B**；有坐骑才写。
- `WEAPON_SLOT_BYTE[11114] = 0x07`（真服 `cd2b6a070101`，以前回落 08）。
- `work/test_acc_equip.py` 长度断言按新模型下移 6B：11 件 90B / 10 件 84B / 少一件 88B。
- `work/test_newbie_char.py` 增加**逐字节**断言：剧情神装状态下 `build_30()` 必须
  等于真服那串 82B 原包。

### 验证
```

```

## 17. 登录后自动弹的「精彩活动」面板 = cmd=1266 活动表原包

**现象**：每次上线（或做完第一个任务 / 用掉一件道具）都会自动弹出同一个面板，
新档也一样。玩家怀疑是「某处的存档快照」。

**结论**：不是角色存档，是**线上服抓包的活动表原包**。

- 存放：`templates.json` 的 `push_1266`，1378 字节，开头是
  `cd07d701 b0 65 5f 6a 69 6e 67 63 61 69 68 75 6f 64 6f 6e 67` → `_jingcaihuodong`。
- 推送点：只有 `local_server3.py` 的 `cmd==1265` 分支（登录初始化最后一步），
  每次登录都推一份。
- 客户端收到这张表就把「精彩活动 / 本服每周福利」面板打开；面板里
  「活动剩余时间 0天」是因为录制时那份表的活动档期早就过了，属正常。
- 与角色无关，所以新档、老档、任何账号都会弹；换账号也不会变内容。

**是否要关**（未改，等玩家定）：
1. 保持现状 —— 与线上服行为一致，只是每次登录弹一次；
2. 每角色只弹一次 —— 存档加 `act_seen` 标记，首次登录后永久不再弹；
3. 完全不推 —— 面板会没有活动数据（不推荐）。

## 18. 每次上线弹「绑定铜币-2,xxx,xxx / 元宝-1749 / 绑定元宝-4050」+ 称号自带

**不是 28 的锅，是 17。** `TPL17_LIVE` 是线上服抓包那一个号的整包快照：

```
idx18 绑铜 ce00232800 = 2,304,000
idx19 绑元 cd0fd2     = 4,050
idx20 铜钱 00         = 0
idx21 元宝 cd06d5     = 1,749
idx22 VIP  00
idx24 称号 cd03fb     = 1019（神界新丁）
```

`build_17` 以前只替换装备 / 等级 / 经验，货币和称号原样带出去：

1. 登录时客户端先按 17 记账（230 万绑铜 / 1749 元宝 / 4050 绑元）；
2. `28` 再把真值推下去 → 客户端按差额弹负飘字，看着像被扣钱；
3. 17 又给头顶挂上「神界新丁」，而 `build_88` 回的是**另一个号的**
   `cd0b7c`（=2940），所以第一次交任务/打怪收到 88，称号就被换掉了。

### 修复
- `build_17` 头部 idx18~21 改写成存档货币、idx22 写 VIP、idx24 写 `cur().title`。
  **必须定宽写**（绑铜 ce+4B / 绑元 cd+2B / 铜钱 1B / 元宝 cd+2B / 称号 cd+2B），
  包长仍为 `197+位移`；走 token 重编码会缩短 2~4B，后面的定长装备段整体前移。
  只有数值超出该宽度（绑元/元宝 >65535、铜钱 >255）才退回 token 重编码。
- `build_88` 只回存档里的称号：有 → 21B `cd+id`，没有 → 19B 空表。
  **不再按等级自动给称号**。
- `Player` 新增 `title` 字段（默认 0，随存档落盘）。老存档没有这个字段 = 没戴称号。
- `182` 新增称号卡分支：`TITLE_CARD = {30059: 1019}`，Lv≥5 才生效，
  消耗 1 张 → `title=1019` → 推 `88 + 178`。以前走「称号系统尚未实现」分支，
  卡用不了；用完又因为 88 是死值，称号还会自己消失。
