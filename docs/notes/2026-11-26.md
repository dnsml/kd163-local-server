## 3. 新发现：30 包武器块第三字节不是固定槽号

同一位置两次抓包不一样：

| 武器 | id | 字节 |
|---|---|---|
| 天枢剑[二阶] | 11235 | `08`（00:16:01 换装回包） |
| 玉衡剑[三阶] | 11328 | `07`（00:54:35 穿回回包；登录 17 包同为 07） |

两把在 `Item.xml` 里都是 `item_kind1=1 item_kind2=1 class_limit=1`（御剑），
`Equip.xml` 也没有任何区分字段，所以**只能按 id 收录真服原值**，不能反推公式。

处置：`local_server3.py` 新增

```python
WEAPON_SLOT_BYTE = {11235: 0x08, 11328: 0x07}
...
_wsb = WEAPON_SLOT_BYTE.get(iid8, 0x08)
out += b"\xcd" + iid8.to_bytes(2, "big") + bytes([_wsb]) + b"\x01\x01"
```

未收录的武器回落 `08`——08 已被 11235 证明是合法武器字节，回落只会让外观编号不精确，
不会把武器画到别的部位（部位由客户端 UI 格固定，与这个字节无关）。

## 6. 30 包尾部块长写错（腰带 / 护腕 / 护符显示空）+ 背包 60 格上限

### 6.1 症状

服务端 `30` 说已穿 9 件，客户端腰带、护腕、护符三格却是空的；背包里的东西也「有件数、看不到」。

### 6.2 30 尾部块长（真正的根因）

真服固定尾部 = 第 12 块 4B + 翅膀块 **20B** + 坐骑块 **6B**，长度与「有没有翅膀/坐骑」无关。
本地旧实现写成「翅膀空 4B / 有 8B，额外 12B，坐骑 4B」，于是：

| 情形 | 旧实现 | 真服 | 后果 |
|---|---|---|---|
| 11 件全满 | 90B | 96B | 客户端从翅膀块开始错位解析，腰带/护腕/护符读成空 |
| 11 件全空 | 68B | 74B | 同上 |

修法（`build_30()`）：

```python
out += _enc30(_wing) + b"\x00" * 15 if wing else b"\x00" * 20   # 翅膀固定 20B
out += b"\xcd" + iid + b"\x0d\x01\x01" if mount else b"\x00" * 6 # 坐骑固定 6B
```

`work/test_acc_equip.py` 长度断言同步 +6B：第一枚戒指 90B、第二枚 92B、满配 96B、
819 卸戒指 94B、卸护符 92B、37 卸槽 1 90B。

### 6.3 背包 60 格上限

真服 `178` 只报 `pos 0~59`。旧 `bag_add()` 没有上限，会一路写到 60/61…，
客户端按 60 格渲染 → 物品「进了包但看不见」，只能 GM 删格才清得掉。

- `BAG_CAPACITY = 60`，`bag_free_pos()` 满包返回 `None`
- `bag_add()` 满包返回 `None` 并记 `[bag] ！！背包已满（60 格），装不下 X xN`
- 商城 `371`：满包且叠不上 → 先拦下回「背包已满」，**不扣钱**
- GM `物品`：满包回执「背包已满（60 格），发不进去」
- 读档：`pos >= 60` 的越界物品搬回 0~59 空位（搬不下则保留 + 告警）
- 新增 `work/test_bag_cap.py`：60 格填满 / 第 61 件拦截 / 满包叠堆 / 越界迁移
