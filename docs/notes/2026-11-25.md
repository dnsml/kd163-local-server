# 2026-11-25 夜间：登录失败与穿首饰闪退

继 11-24 的首饰修复之后，真机验证时连爆两个问题，都在这一轮定位并修掉。

## 1. 登录弹「安全连接验证失败，请检查设备时间后重试」

### 现象

- 模拟器重启后客户端点登录，立刻弹这个提示，服务端 `server.log` **一行连接记录都没有**。
- 设备时间与本机时间完全一致（同为 21:23），所以跟时间、证书有效期无关。
- `patch/exact.pem` 是 1151B 纯 LF，文件没被换行破坏。
- 手动用 Python 直接连 `127.0.0.1:9000` 做 TLS 握手，TLS1.3 正常，证书也发出来了。

### 根因

服务端只接受 TLS1.2+。用系统 Python 3.8（OpenSSL 1.1.1）模拟老客户端逐版本握手：

```
TLS1.0 FAIL SSLError [SSL: TLSV1_ALERT_PROTOCOL_VERSION]
TLS1.1 FAIL SSLError [SSL: TLSV1_ALERT_PROTOCOL_VERSION]
TLS1.2 OK   TLSv1.2 ECDHE-RSA-AES256-GCM-SHA384
```

老客户端走的是 TLS1.0/1.1。Python 3.13 底下的 OpenSSL 3.x 默认 `minimum_version = TLSv1_2`，
握手阶段直接回 `alert protocol version`，客户端只能显示成「安全连接验证失败」——
文案把原因引向时间和证书，实际是协议版本。

### 修复

`local_server3.py` 的 `ssl_ctx()`：

```python
c.minimum_version = ssl.TLSVersion.TLSv1   # 放开下限
c.set_ciphers("ALL:@SECLEVEL=0")          # 一并放宽容错级别
```

改完复测：TLS1.0 / 1.1 / 1.2 全部可握手。

### 附带发现：真正让客户端连不上本地的还有路由

TLS 放开后依然零连接，`netstat` 看到设备在连 `124.223.56.18:80`（线上服）。
客户端用的是 IP 字面量，不走 DNS，所以 hosts 无效，必须靠：

- 设备侧 `iptables -t nat OUTPUT -m owner --uid-owner 10060 -p tcp --dport 9000/80 -j DNAT`
- `adb reverse tcp:9000`、`tcp:8080 tcp:80`

模拟器重启会把这两样都清掉。`bash switch.sh coexist` 一条命令恢复。

## 2. 穿戒指当场闪退

### 现象

21:30:07 客户端发 `182 1601`（格 22 = 飞仙戒指），服务端依次回
`182 / 29 / 28 / 30 / 818 / 178`，1 秒后 `对端关闭`，logcat 里是
`app died, no saved state`（Unity 原生层崩溃，没有 Java 栈）。
Breakpad 的 dmp 只有 1256B，除了 header 全是 0，拿不到崩溃地址。

### 根因

上一版 `build_30()` 有个错误假设：**30 包必须锁死 82B**，
于是每穿一件首饰就用「6B 实槽替换 4B 空槽」后，再从尾部填充里扣掉 2B 把总长压回 82B。
总长是保住了，但**后面所有字段整体前移**，客户端按尾部结构解析就读错。

真服抓包证明 30 本来就是变长的，`logs/relay.log` 里各长度出现次数：

| 长度 | 次数 |
|---|---|
| 96 | 211 |
| 86 | 156 |
| 82 | 63 |
| 88 | 6 |
| 80 | 4 |

真服 96B 样本（23:52:25）：

```
cd2b64 01 0101  cd2b65 02 0101  cd2b66 03 0101
cd2b67 04 0101  cd2b68 05 0101  cd2b69 06 0101
cd2842 0b 0101  cd2842 0c 0101  cd2841 09 0101  cd2841 0a 0101
cd2c40 07 0101
00000000 ce00061a82 ...
```

即：6 个装备槽 → 4 个首饰槽（戒指 9/10、护符 11/12）→ 槽 7 → 尾部字段。
空首饰槽 4B，实槽 6B，**总长跟着变**。

### 修复

去掉裁尾填充的逻辑，首饰区按真服语义直接变长，尾部固定 24B：

- 无首饰：82B（与真服 82B 样本逐字节一致）
- 1 件：84B
- 2 件：86B

回归 `work/test_acc_equip.py` 的断言从「必须 82B」改成「7 装备 + 2 首饰 = 86B」，
13 项全 PASS。

## 5. 「背包里三件东西用不了、之后会变成别的物品」

### 现象

每次上线背包最上面固定有三件用不了的东西，打完怪 / 交完任务后
「同一格」忽然变成别的物品。用户截图一：绑定铜钱卡×10、10绑定元宝、
5级新丁礼包；截图二：中级强化仙玉、绿色洗炼石、神器之魄……

### 根因

客户端打开背包发 `177`，服务端没有 177 分支，落到通用那一档
「`cmd+1` 在 TPL_PUSH 里就回模板」，而 `TPL_PUSH[178]` 录制的是
**新号三件套**那 23 字节：

```text
40 03  00 cd4ede 00 01 0a  01 cd4fd0 00 01 01  02 cd5209 00 01 01
       ↑20190 绑定铜钱卡×10  ↑20432 10绑定元宝  ↑21001 5级新丁礼包
```

于是每次开背包，这三件就被盖到槽 0/1/2 上 —— 服务端背包里根本没有，
点「使用」自然没反应；等打完怪推了动态 178，同一格又变回强化仙玉，
看起来就是「东西变成别的物品」。

### 修复

`177` 显式回动态全量 178：

```python
if cmd == 177:
    body = bag_proto.build_178(bag_view())
    return 178, body, []
```

回归加一条：`177` 回的 178 条数必须等于当前背包件数、且长度不是 23B。

### 顺带修掉

`178` 差异日志用到 `cur().bag_sent`，但 `Player` 是 `__slots__` 类，
直接赋值抛 `AttributeError` —— 已把 `bag_sent` 加进 `__slots__` 并在
`__init__` 里置 None。

## 23:55 闪退定性：首饰「一件占两格」是根因，客户端 SIGABRT

玩家反馈「有 bug 还是，而且闪退了」。logcat 直接给出结论：

```
23:41:01.880  got packet, seq = 44, cmd = 819
23:41:01.880  loading end, m_depth = 0
23:41:01.919  ActivityManager: Process com.kdxx.local1 (pid 5608) has died
23:41:01.919  Zygote: Process 5608 exited due to signal (6)     ← SIGABRT
```

服务端没有任何异常，`29/28/30/178` 都发出去了，客户端连 `cmd=29` 都没打出来就死了
—— **死在 819 回包的处理里**，还没轮到后面的推送。

### 1. 线上服真实语义（决定性，推翻旧结论）

23:25:24~29 连续四个 `182`，逐个看 `30` 只多了一条：

```
23:25:24  182 hex=3a01 → 30 多 cd28420c0101（护符 / 槽12）
23:25:26  182 hex=3b01 → 30 多 cd28420b0101（护符 / 槽11）
23:25:27  182 hex=3801 → 30 多 cd2841090101（戒指 / 槽9）
23:25:29  182 hex=3901 → 30 多 cd28410a0101（戒指 / 槽10）
```

同一个 `178` 里这四件**各占一个独立包格**（38/39/3a/3b）。
所以 9 和 10 是「两个戒指槽」、11 和 12 是「两个护符槽」，
四件独立物品；**不是**一件同时写两格。

旧实现按「成对镜像」写（9=10、11=12 同一个 id），后果：

- 面板多画一件，玩家说「还有两个槽是空的」其实是数量对不上；
- 属性按两格算 → 需要特判剔除 10/12 才对得上，改成独立物品后这种特判反而少算；
- 卸下时两格一起消失、`178` 只回一件 → **客户端账面不一致，断言 abort**。

### 2. 改法

- `acc_slots_of(slot)` 永远只返回 `(slot,)`，一件一格；
- 新增 `equip_slot_for(kind2)`：首饰同类优先放空槽（9→10、11→12），两格都满换主槽；
- `all_attrs()` 去掉「剔除 10/12」，四格各算各的；
- 读档迁移：旧档 9/10、11/12 里 id 相同的，清掉配对那格（那是分身，不是第二件）；
- `819`：真的卸下点中的那一格，但**回包改成 `cmd=1` 文本**（线上服同形），
  **绝不回 819** —— 回 819 空包就是这次闪退的直接触发点；
- GM `装备` / `脱装备` 同步改成单槽 + 推 `29/28/30/178`。
