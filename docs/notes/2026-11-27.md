## 相对原包做的两处改动（重要）

1. **`kd163-http.service` 的 `ExecStart` 写死 IP**
   原包是 `local_http.py 80 $KD163_HOST` —— systemd **不展开 `$变量`**，
   会把这个字面量当成广播 IP，客户端拿到的资源 URL 就是坏的。
   已改为：
   ```ini
   ExecStart=/usr/bin/python3 local_http.py 80 129.204.52.72
   ```

2. **`kd163-admin.service` 监听改 `0.0.0.0`**
   ```ini
   Environment=KD163_ADMIN_HOST=0.0.0.0
   ```
   绑定非本机时 `admin_auth` 会自动要求登录；这里直接用了本地的 `admin.json`，
   所以账号是 `admin` / `kd163admin`，不会重新生成密码。

3. **资源服新增 `KD_ASSETS_REWRITE=1`（公网部署必须开）**
   `assets.txt` 和 `meta.xml` 里原本写死 `http://124.223.56.189/...`。
   本地开发靠 DNAT 连旧 IP，所以原样下发是对的；但公网独立部署时客户端直连
   `129.204.52.72`，再让它去 `124.223.56.189` 下 110 MB 资源包就跑到别人服上去了。
   已在 `local_http.py` 里加开关（默认关，不影响本地）：
   ```ini
   Environment=KD_ASSETS_REWRITE=1
   ```
   开启后下发内容实测：
   ```text
   assets_url=http://129.204.52.72:80/mhsj_res.zip
   <uri>http://129.204.52.72/assets/avatars/1_body.png</uri>
   ```

## 客户端怎么连过来

客户端把服务器 IP 写死在 `server-list.xml`（`124.223.56.189`），三种接法：

1. **手机/模拟器 DNAT（最快，不改包）**
   ```bash
   su 0 iptables -t nat -A OUTPUT -d 124.223.56.189 -p tcp --dport 80 \
        -j DNAT --to-destination 129.204.52.72:80
   su 0 iptables -t nat -A OUTPUT -d 124.223.56.189 -p tcp --dport 9000 \
        -j DNAT --to-destination 129.204.52.72:9000
   ```
   缺点：设备重启后失效，每台设备都要设。

2. **改 APK 内置 `server-list.xml` 重打包**（推荐给玩家）
   把 `124.223.56.189` 全替换成 `129.204.52.72`，重签名。
   注意资源包 `mhsj_res.zip` 里也有同名文件，要一起改，否则客户端会把
   本地改过的覆盖回去。

3. **本地资源服当跳板**
   本机 80 端口的 `local_http.py` 已经会把资源里的 IP 替换成 `HOST_IP`：
   若把 `HOST_IP` 设成 `129.204.52.72`，客户端从本机 80 拉一次资源，
   `server-list.xml` 就变成新 IP。前提是本机 80 一直开着。

## 证书注意（实测更正）

客户端**把 PEM 整个内嵌在 `classes.dex` 里做 pinning**，握手后逐字节比对。
所以「只改 URL 不换证书」的做法行不通 —— 服务端换证书后，客户端握手成功
但一个字节都不发就断开（`handle_tls` 日志：`握手成功 … 收到字节 0`）。

正确做法（本次已落地）：**等长替换 DEX 内嵌证书**，生成 DER 长度必须与原来
完全一致的证书（`DER=808 / PEM=1151`），`work/gen_cert.py` 自动调整 serial
长度 + 一个固定 OID 扩展来凑足长度：

```bash
python work/gen_cert.py            # -> patch/newcert/exact_new.pem / pub.key
python work/dexpatch.py            # 内嵌 PEM 等长替换（delta=0）
python work/verify_dex.py work/apk_out/classes_new.dex
```

证书主体（与 APK 内嵌、服务端 `patch/exact.pem` 三处必须同一张）：

```text
subject=CN=129.204.52.72
X509v3 Subject Alternative Name: IP Address:129.204.52.72
DER=808  PEM=1151  （与原证书完全等长）
```

⚠️ 以后换 IP 要**同时**改三处：`classes.dex` 的 7 个 URL + 内嵌证书、`AndroidManifest.xml`
的 `client.apk` URL、服务端 `patch/exact.pem|key`。任一处漏了就是「连不上」或「握手后被断开」。

### 要改的三处

| 位置 | 内容 | 工具 |
|---|---|---|

| `AndroidManifest.xml` | `http://124.223.56.189/client.apk`（UTF-16LE 字符串池） | `work/axmlpatch.py` |
| `META-INF/` | 删除旧签名 | `work/repack_apk.py` |

DEX 里的 7 个 URL（改后实测）：

```text

http://129.204.52.72/legacy/equipment.php

http://129.204.52.72/server-list.xml
http://129.204.52.72/version.txt
https://129.204.52.72:9000/auth
```

### ★ DEX 补丁必须等长（踩了两次）

第一版重建 `string_data` 区、把后续 section 整体平移（-7 字节），Android 直接拒加载：

```text
Failure to verify dex file ...: Offset(1605953) should be aligned by 4 for map.
Shorty vs. primitive type mismatch: 'I', 'Lcom/aiyou/views/UmengShareMenu$MenuAdapter;'
```

第二版加了 4 字节 padding，仍因偏移变化触发同一类校验错误。
最终方案：新字符串区**不超过原区时补零到原长度**（`delta=0`），所有 section 偏移不变：

```python
if len(block) <= old_span:
    block += b"\x00" * (old_span - len(block))
    delta = 0
```

改完补 header checksum（adler32）和 SHA-1，`work/verify_dex.py` 校验
magic / file_size / checksum / SHA1 / `map_off % 4` / section 递增 / MUTF-8 长度 / 各 off 越界，
全部 OK 才装。
