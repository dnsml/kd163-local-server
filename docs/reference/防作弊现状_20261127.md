# 防作弊现状（本地服，2026-11-27 逐条核对代码）

> 结论先说：**不是「没有防作弊」**。经济、战斗、背包、合成都是服务端权威，
> 改包只能改「想做什么」，改不了「有多少、扣多少、打多少」。
> 真正的窟窿只有两处：**移动坐标** 和 **任务接/交**。

## 一、逐条核对结果

| 入口 | 服务端怎么处理 | 有没有校验 | 结论 |
|---|---|---|---|
| `371` 商城购买 | 查 `MALL[(area,iid)]` 单价，按 `AREA_CUR` 取钱包，余额不足回「对应货币不足」 | ✅ | 改包买不了买不起的东西（实测见 §三） |
| `182` 使用道具 / 穿戴 | **只认服务端背包那一格**（`cur().bag[pos]`），客户端只给格号 | ✅ | 不能凭空穿装备；格子空就回「此背包位置没有可使用物品」 |
| `831` 材料合成 | `synth_apply()` 查材料够不够，不够回文本 | ✅ | 不能无中生有 |
| `145` 发起战斗 | payload 只有 4 字节（怪 id），伤害由服务端算，`151`/`148` 下发 | ✅ | 协议层没有「加伤害」的入口 |
| `128` 过图跳点 | 查 `JUMPS` 表，查不到就留在原地 | ⚠️ 弱 | 只能跳到表里存在的跳点，但**不校验等级/解锁条件** |
| `817` 装备栏上报 | 只用来记 `weapon_wire`（客户端武器协议槽是 07 还是 08），**不改装备** | ✅ | 客户端说了不算 |
| `115` 移动坐标 | `cur().pos_x/pos_y = payload[0:2]`，直接写 | ❌ **无** | 单步距离、穿墙、加速都不校验 |
| `211` 接任务 | 收到任意 `ce+u32` 都当成接任务，直接回显 | ❌ **无** | 可以跳过前置，接任意任务 id |
| `214` 交任务 | 只查 `done_quests` 防重复，**不查 `quest_active`/`quest_ready`**（仅 400702 有特例） | ❌ **无** | 可以跳任务链，把能交的任务一次性交掉领奖 |
| `371` 数量 | `cnt` 是 u8（0~255），无额外上限 | ⚠️ | 靠单价×数量自然拦住，不会溢出 |

## 二、两处真窟窿能做什么

### 1. `115` 坐标不校验 → 瞬移 / 加速

客户端每走一步发一条 `115 [x][y]`（一格一字节），服务端照单收下并回两条 `118`。
没有「单步最大距离」判断，所以：

- 改包一次跨半张图 → 角色瞬移；
- 高频发 115 → 移速翻倍。

**影响**：只影响跑图效率，不产生物品和货币。战斗仍需 `145` 且由服务端判定。

**修法**：`115` 分支里比较 `abs(dx),abs(dy)` 与 `KD_MAX_STEP`（默认 3 格，
    真机正常一步 1~2 格），超了就回退到服务端记录的坐标、只回一条 `118`。
    注意必须留余量，客户端过图后第一次 115 可能跳一大格。

### 2. `211`/`214` 任务无状态校验 → 跳任务领奖

- `211` 任何任务 id 都接；
- `214` 只防「同一任务交第二遍」，不防「没接就交」。

组合起来 = 把所有 `QUEST_REWARD` 里的任务挨个交一遍，拿走全部经验和铜钱。
每个任务只能拿一次（`done_quests` 落库），所以是「一次性收益」，不是无限刷。

**影响**：能瞬间升到任务表给到的最高等级、拿几十万铜钱。这是真正影响平衡的一条。

**修法**：`214` 里加一道
```python
if qid_int != cur().quest_active or not cur().quest_ready:
    return 1, err_text("任务条件未满足"), []
```
并把 `211` 限制在「当前任务或任务链下一个」。
⚠️ 必须先摸清客户端重登时会不会补发历史 214（现在代码里 `done_quests` 分支就是为了
兜这种情况），加严之前要用真机跑一遍：接任务 → 退出 → 重进 → 交任务，确认不误伤。

## 五、一句话总结

`182`/`371`/`831`/`145` 这四条主线是稳的，改包占不到便宜；
`115` 能瞬移、`211+214` 能跳任务领一次奖励 —— 公开开服前把这两处补上就够了。
