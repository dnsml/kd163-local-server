# 上线部署清单（公网服务器）

> 结论：**能部署，但不是把目录一拷就完事**。账号密码、后台登录已经内置；
> 仍要注意：游戏帧在 `/auth` 之后是明文、GM 靠本机文件。下面按
> 「必须改 / 建议改 / 直接可用」分开写。

## 一、要跑几个进程

| 进程 | 端口 | 作用 | 公网 |
|---|---|---|---|
| `local_server3.py 9000 patch/xxx.pem patch/xxx.key` | 9000 | TLS 终结 + `/auth`，同端口跑明文游戏协议 | ✅ 必须 |
| `local_http.py 80 <本机IP>` | 80 | 资源服：`/server-list.xml`、`assets/**` | ✅ 必须 |
| `admin_server.py 8899` | 8899 | 网页后台（GM/在线/账号/账号密码） | ⚠️ 只绑 127.0.0.1；对外要登录 + HTTPS |
| `capture_proxy.py` / `relay.py` | 19000 | 抓包镜像（开发用） | ❌ 不要上 |

依赖：**纯标准库，Python 3.8+ 即可**（`sqlite3`、`ssl`、`http.server`），不需要 pip 安装。

需要一起带上的文件：

```
*.py                    # 服务端模块（local_server3/battle/bag_proto/grant/…）
state_store.py
res_cfg/                # Item/Quest/Scene/Levelup/Pet… 配置表
mirror/                 # 资源服要发的静态资源（assets/**）
templates.json  replay_sc.json  tpl_extra.json
admin.html  admin_login.html
account_policy.py  admin_auth.py
patch/<cert>.pem  patch/<cert>.key     # 必须与改包 APK 内嵌的信任根同一对
```

`server_state.db`、`player_state*.json`、`backups/`、`logs/` 是运行数据，部署时不要带；
`server_state.db` 会自动建。

## 二、上线前必须改的四件事

### 1. 账号鉴权（唯一的硬门槛）

两种账号，可以混用：

| 类型 | 怎么来 | `/auth` 行为 |
|---|---|---|
| **有密码** | 后台「新建游戏账号」生成（8 位随机账号 + 10 位随机密码，只存 pbkdf2 哈希） | 校验密码，错 401；通过后 6 小时内才能进游戏（防自组包跳过 `/auth`） |
| **只放行** | `allow_accounts.py add` 或 `sync`（老账号/主号） | 不校验密码，只看名单 |

- 名单外账号：`/auth` 403、登录 17/20 被拒，**不建存档**；
- 没配 `accounts.json` → 全放行（开发默认）；名单为空/JSON 坏 → **全部拒绝**（fail closed）；
- 改文件不用重启，下一次请求就按 mtime 重新加载；
- `open: true` = 放开新账号注册（已有账号的密码仍然校验）；
- 后台第一次生成账号时，会自动把库里现有角色写进 `allow`，不会把老玩家锁在门外。

```bash
python3 work/allow_accounts.py sync|add|remove|list|off
```

**边界**：客户端登录包里有密码，但游戏内的 17 包没有密码字段；密码保护的是
「拿到 17 之前必须过 `/auth`」这一层。真要做到每个包都鉴权，得改客户端协议。

### 2. 证书 + 改包必须成对

客户端把证书当**信任根**，且证书 SAN 写的是 IP：

```
subject=CN=124.223.56.189
X509v3 Subject Alternative Name: IP Address:124.223.56.189
```

公网部署两条路：

- 服务器 IP 不变（继续用 `124.223.56.189`）→ 证书和现成 APK 都能直接用；
- 换 IP → 重新生成证书（脚本只支持 **IP SAN**，不支持域名）：

```bash
python gen_cert_exact.py --cn <新IP> --want 1151 --out patch/srv
# 产出 patch/srv.pem + patch/srv.key；PEM 长度必须正好 1151 才能原地塞进 dex
python patch_apk.py --src kd163.apk --out kd163_new.apk --host <新IP> \
                    --cert patch/srv.pem --key patch/srv.key
```

只换服务端证书、不改包 → 客户端「安全连接验证失败」。想用域名：先改
`gen_cert_exact.py` 的 `subjectAltName` 为 `DNS:<域名>`，且域名长度 ≤ 14（dex 原地改写限制）。

`patch_apk.py` 是**原地改写** dex 里的 `http(s)://124.223.56.189`，新 host **长度不能超过 14 字符**
（`124.223.56.189` 正好 14）。域名太长会写不下，用短域名或直接换同长度 IP。

客户端端口写死：**80 资源、9000 游戏**，所以公网要开这两个（80 不能用就做 80→8080 的端口映射，
客户端不会自己改端口）。

### 3. 后台与 GM 通道不要暴露

- `admin_server.py` 默认只绑 `127.0.0.1`，别设 `KD163_ADMIN_HOST=0.0.0.0` 放到公网；
- GM 是「往 `logs/gm.cmd` 写一行」，本质是本地文件权限，公网机器上只给运维账号可写；
- `logs/server.log` 里有账号、背包、聊天等内容，别挂到 web 目录。

### 4. 后台登录（对外必须开）

后台默认只绑 `127.0.0.1`，本机访问**不要求登录**；绑 `0.0.0.0` 时**强制登录**，
没有 `admin.json` 会自动生成 `admin` + 12 位随机密码并打印在启动日志里。

- 管理员密码只存哈希：`python3 work/admin_password.py set admin 你的密码`；
- 登录态是 HttpOnly + SameSite=Strict 的 Cookie，12 小时过期，进程重启即失效；
- 所有写操作要求 `X-Requested-With: KDAdmin`（防 CSRF）；
- 同一 IP 连错 5 次锁 60 秒；
- **Nginx 反代**时后台看到的来源是 127.0.0.1，必须设 `KD_ADMIN_REQUIRE=1` 才会强制登录；
- 也可以让后台自己走 HTTPS：`KD_ADMIN_TLS=1`（默认用 `patch/exact.pem|key`，可用
  `KD_ADMIN_CERT` / `KD_ADMIN_KEY` 换），直接用 `https://IP:8899` 访问；
- 登录接口**不记录密码**：排障日志只打字段名和长度，历史日志里的明文已脱敏。

## 三、Linux 上的路径与解释器（没有硬编码）

服务端代码里**没有写死的盘符或绝对路径**：所有文件都以 `HERE = 模块所在目录` 为基准
（`res_cfg/`、`mirror/`、`templates.json`、`logs/`、`backups/`、`server_state.db` 都跟着代码走）。
只有启动脚本里的 Python 路径是 Windows 的，已经处理：

- `work/start_all.sh` 依次找 `$PYTHON` → `python3` → `python` → Windows 常见安装位置，
  Linux 上直接 `bash work/start_all.sh` 即可；没有 adb 会自动跳过 reverse/DNAT 与客户端登录；
- 证书参数支持相对路径，**按项目目录解析**而不是 cwd：

```bash
cd /opt/kd163 && python3 local_server3.py 9000 patch/exact.pem patch/exact.key
# 从别的目录启动也等价：
python3 /opt/kd163/local_server3.py 9000 patch/exact.pem patch/exact.key
```

- `deploy/` 下已带 systemd 单元，见 `deploy/README.md`（含 80 端口的
  `CAP_NET_BIND_SERVICE` 配置）；
- 存档、日志、备份目录不存在会自动创建，不需要预建。

## 四、部署步骤（Linux + systemd）

```bash
# 1) 放代码
mkdir -p /opt/kd163 && cd /opt/kd163
# 上传：*.py res_cfg mirror templates.json replay_sc.json tpl_extra.json admin.html patch/

# 2) 先手动起一遍，确认没有缺文件
python3 local_server3.py 9000 patch/exact.pem patch/exact.key
python3 local_http.py 80 127.0.0.1        # 第二终端

# 3) systemd（也可以直接 cp deploy/*.service /etc/systemd/system/）
cat >/etc/systemd/system/kd163-game.service <<'EOF'
[Unit]
Description=kd163 game server
After=network.target
[Service]
WorkingDirectory=/opt/kd163
Environment=PYTHONIOENCODING=utf-8
Environment=KD_STATE_BACKEND=sqlite
ExecStart=/usr/bin/python3 local_server3.py 9000 patch/exact.pem patch/exact.key
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
EOF

cat >/etc/systemd/system/kd163-http.service <<'EOF'
[Unit]
Description=kd163 resource server
After=network.target
[Service]
WorkingDirectory=/opt/kd163
Environment=PYTHONIOENCODING=utf-8
ExecStart=/usr/bin/python3 local_http.py 80 127.0.0.1
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now kd163-game kd163-http
```

防火墙：只开 `80/tcp`、`9000/tcp`（SSH 另算），**不要**开 8899。

## 五、数据与备份

- 存档在 `server_state.db`（WAL 模式）。备份用 SQLite 自己的接口，别直接 `cp`：

```bash
sqlite3 /opt/kd163/server_state.db ".backup '/backup/kd163-$(date +%F-%H%M).db'"
```

- 每 10 分钟 `backups/` 里还会有一份「写前快照」（JSON），保留最近 20 份/角色；
- 回滚单角色：`state_store.save(账号, json.load(备份))`，或直接 SQL 改 `data` 列。

## 六、容量与风险（如实说）

### 6.1 实测资源占用（2026-11-26 本机，1 个在线连接挂机）

| 进程 | 端口 | 工作集 | 私有内存 | 峰值工作集 |
|---|---|---|---|---|
| `local_server3.py` 游戏服 | 9000 | 49.6 MB | 30.1 MB | 56.7 MB |
| `local_http.py` 资源服 | 80 | 12.7 MB | 11.6 MB | 22.2 MB |
| `admin_server.py` 后台 | 8899 | 34.8 MB | 14.5 MB | 42.1 MB |
| **合计** | | **≈ 97 MB** | **≈ 56 MB** | ≈ 121 MB |

- **CPU**：连续 15 秒采样，三个进程 CPU 时间增量都是 `0.00 s`（空载真的不烧 CPU）。
  资源服累计只用了 14.3 s CPU —— 那是把 110 MB 资源包发出去的成本，属于 IO 为主。
- **内存不随挂机增长**：15 秒内工作集完全不变（49.6/12.7/34.8），没有泄漏迹象。
  配置表（Item/Quest/Skill/PetEquip 等）启动时一次性载入，约占 25~30 MB，是固定开销；
  单个在线角色的 Python 对象只有几 KB（背包 60 格 + 任务 53 条 + 装备 11 格），
  一百人在线大约再加 1~3 MB。
- **磁盘**：部署包解压后约 250 MB（其中 `res_update/mhsj_res.zip` 110 MB）；
  `server_state.db` 现在 52 KB；`logs/` 是增长最快的目录（逐包日志，一个月能到几 GB）。

### 6.2 网络占用（按协议实测，不是估算）

| 场景 | 流量 | 依据 |
|---|---|---|
| 挂机心跳 `cmd=4` | 上行 5 B / 10 s，下行同样 5 B 左右 | 日志里 2895 条心跳，平均长度 5.0 B |
| 一次登录 | 下行 ≈ 3.4 KB（`818`850B ×2 + `43`345B ×2 + `17`205B + `178`156B + `30`96B + `957`82B …），上行 ≈ 0.1 KB | 日志登录窗口实测 |
| 一场战斗 | 每回合 `145`/`148`/`151` 几包，单包几十到一百多字节，一场 20 回合约 3~5 KB | 协议包长 |
| 首次进游戏 | 资源包 110 MB（每台新设备一次） | `res_update/mhsj_res.zip` |

**结论**：稳态几乎不吃带宽 —— 一个挂机玩家约 1 B/s，一百人同时挂机也就 100 B/s（≈0.8 kbps）。
真正吃带宽的只有**首次资源下载**：110 MB/人。
按「5 人同时首装、希望 3 分钟下完」算，需要约 25 Mbps 上行；
1 人 5 分钟下完 ≈ 3 Mbps。所以小服 5~10 Mbps 上行够用，人多再上 CDN/对象存储托管资源包。

### 6.3 配置建议

| 规模 | CPU | 内存 | 带宽 | 磁盘 |
|---|---|---|---|---|
| 内测（≤20 人） | 1 核 | 1 GB | 5 Mbps | 10 GB |
| 小服（≤100 人） | 2 核 | 2 GB | 10 Mbps（资源走 CDN 更省） | 20 GB |
| 更大 | 先压测再定 | — | 资源必须外置 | 日志要轮转 |

### 6.4 风险

| 项 | 现状 | 说明 |
|---|---|---|
| 并发 | Python 线程 + SQLite WAL | 几十人在线没问题；上百人开始要压测，再往上换 MySQL/Postgres + 多进程 |
| 协议 | `/auth` 走 TLS，**游戏帧是明文** | 能被抓包/伪造。小规模内测可接受；公开服建议后续把整条链路包进 TLS 或加帧签名 |
| 反作弊 | **经济/战斗是服务端权威，移动和任务是窟窿** | `371` 查价查余额、`182` 只认服务端背包、`831` 查材料、`145` 伤害服务端算 —— 这四条改包占不到便宜；但 `115` 坐标直写（可瞬移）、`211`+`214` 不查任务状态（可跳任务领一次奖励）。详见 `docs/reference/防作弊现状_20261127.md` |
| 热更新 | 改代码要重启 | 重启会断线，建议凌晨维护窗口 |
| 日志 | 明文文件，逐包记录 | 每天切分/清理，否则一个月几个 GB |

## 七、本地开发环境不要照搬

这些只用于模拟器连本机，公网服务器上一律不需要：

- `adb reverse tcp:8080/9000/19000`；
- 设备端 `iptables DNAT`（把写死 IP 转到 127.0.0.1）；
- `KD_GUARD`（防止误连线上服的 REJECT 规则）；
- `capture_proxy.py` 的 19000 镜像。
