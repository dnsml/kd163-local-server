# 数据库结构（server_state.db）

> 2026-11-26 23:3x 实测。文件在项目根目录，SQLite 单文件，WAL 模式。
> 同一目录会出现 `server_state.db-wal` / `-shm`，是正常临时文件，备份时用 `.backup`。

## 一、三张表

```
player   一行 = 一个账号的角色存档（26 行）
online   谁在线（登录写入，断开删除；1 行表示当前有人）
meta     预留的键值表（现在是空的）
```

### player

| 列 | 类型 | 含义 |
|---|---|---|
| `acct` | TEXT **主键** | 账号（登录用的那串；主号 1784366） |
| `id` | INTEGER | **展示用编号**，后台「ID」列；不是主键，老库启动时自动补列回填 |
| `name` | TEXT | 角色昵称 |
| `level` / `exp` / `exp_need` | INT | 等级 / 当前经验 / 升级所需 |
| `cls` | INT | 职业：1御剑 2逍遥 3幻羽 4法尊 5破军 6未转职 |
| `sex` | INT | 1 男 / 2 女 |
| `scene` / `x` / `y` | INT | 最后下线的场景与坐标 |
| `bind_copper` | INT | 绑定铜钱（老字段名 `coin`） |
| `bind_gold` | INT | 绑定元宝（老字段名 `bind_yuanbao`） |
| `copper` | INT | 铜钱（老字段名 `tongqian`） |
| `gold` | INT | 元宝（老字段名 `yuanbao`） |
| `vip` / `title` | INT | VIP 等级 / 当前称号 id（0=没有） |
| `bag_count` | INT | 背包件数（只是冗余统计，真数据在 `data.bag`） |
| `rev` | INT | 乐观锁版本号，每次落盘 +1 |
| `data` | TEXT | **完整存档 JSON**（背包/装备/妖灵/任务/衣柜…） |
| `created_at` / `updated_at` | TEXT | 建号 / 最后落盘时间 |

`data` 里的键（和旧 `player_state*.json` 完全一致）：

```
name sex has_char level exp need class coin bind_yuanbao tongqian yuanbao
yueli vip_level vip_until mp_add wing wardrobe title scene pos_x pos_y
quest_active quest_ready quest_done equip enhance bag pets spirit_bag spirit_slot ver
```

### online

| 列 | 含义 |
|---|---|
| `acct` | 账号（主键） |
| `cid` | 连接号（`c001` 这种） |
| `since` / `seen` | 登录时间 / 最后刷新 |

### meta

`key` / `value`，目前没用（留给以后存版本号、活动开关）。

## 三、常用查询

```bash
sqlite3 server_state.db "SELECT id,acct,name,level,gold FROM player ORDER BY level DESC LIMIT 10;"
sqlite3 server_state.db "SELECT acct,json_extract(data,'$.quest_active') FROM player WHERE level>40;"
sqlite3 server_state.db "SELECT acct,name FROM player WHERE data LIKE '%11114%';"   # 谁穿着某件装备
sqlite3 server_state.db ".schema player"
```

Python 里更安全（参数化）：

```python
import state_store as S
d, rev = S.load("1784366")         # 读整份存档（dict）
S.save("1784366", d, rev)          # 带版本号写回
```

## 四、为什么这么设计

- **高频字段拆列**（等级/货币/坐标/称号/背包件数）：后台列表、统计不用解析 JSON；
- **复杂结构放 `data`**：背包/装备/妖灵/任务结构经常变，拆表会改到吐；
  同一份 JSON 也能直接回灌旧版 `player_state*.json`；
- **`acct` 做主键**：账号天然唯一，不需要额外自增主键；
- **`rev` 乐观锁**：同一账号两处同时写，后写的能知道「我拿的是旧版本」；
- **SQL 全参数化**：`state_store.py` 里没有任何字符串拼接 SQL；账号另有一层
  `[A-Za-z0-9_.-]{1,64}` 白名单，非法账号连库都不碰。

## 五、备份与恢复

```bash
# 备份（不要直接 cp，WAL 模式会漏最后几条）
sqlite3 server_state.db ".backup 'backup-20261126.db'"

# 看某个号的历史快照（每次写盘前自动留）
ls backups/player_state_1784366_*.json | tail

# 恢复单个角色：把 JSON 读出来塞回去
python -c "import json,state_store as S; d=json.load(open('backups/xxx.json')); S.save('1784366', d, 0)"
```

## 六、和旧存档的关系

`player_state*.json` 仍然保留：

- 新服第一次读到某账号、库里没有时，会**懒迁移**导入；
- `KD_STATE_BACKEND=json` 可整体回退旧文件后端；
- 但正常运行时以 `server_state.db` 为准，JSON 不再更新。
