## 二、性别编码：`1=男 / 0=女`（不是 01/02）

- 真服 12:38 选「男」→ cmd=20 末字节 `01`
- 本地客户端 12:55 选「女」→ cmd=20 末字节 **`00`**

```
010102 a9 3930303030303030 35 da002b <43B token>
ac e591bce5bbb6e88ba5e6a2a6      00
   ↑昵称 呼延若梦(12B)            ↑女
```

所以以前 `_sx if _sx in (1,2) else 1` 会把所有女生都建成男生。

## 三、本地服改动

### 1. `parse_create_role()`（local_server3.py）

取**最后一个**合法 sfield 当昵称（第一个是账号、第二个可能是 token），
末字节归一化：

```python
raw = payload[i + 1 + n] if i + 1 + n < len(payload) else 1
sex = 1 if raw == 1 else 2      # 1=男；0=女（2 也按女，兼容旧猜测）
```

### 2. `build_28()`：账号/昵称动态拼

模板 `PLAYER_28_TPL` 头部写死 `a7"1784366" a6"萌新"`，**28 才是客户端显示角色名的地方**。
不动态化的话，新建的角色在场景里名牌还挂着「萌新」（第一次实测就是这个现象）。

```python
_af = sfield(cur().acct or PRIMARY_ACCOUNT)
_nf = sfield(cur().name) if cur().name else b"\xa0"
shift = (len(_af) - 8) + (len(_nf) - 7)
b = bytearray(b"\x0c" + _af + _nf + PLAYER_28_TPL[16:])

def at(o):
    return o + shift

b[at(16)] = cur().cls
b[at(18)] = cur().level
b[at(25):at(27)] = min(cur().exp, 65535).to_bytes(2, "big")
```

与 `build_17()` 同一套规则，主号（7 位账号 + 萌新）shift=0，行为不变。

> 注意：build_28 内部 `tokenize -> render` 会把 `ce+4B` 压成 `cd+2B`，
> 所以发出的 28 常是 71B 而不是模板的 73B，客户端接受，属正常。

### 3. 无角色 / 建角分支（已在上一次改动里）

```python
if not cur().has_char:
    conn.sendall(pack(1, seq, b"\x01\xa0"))
    continue

if cmd == 20:
    _nm, _sx = parse_create_role(payload)
    ...
    create_character(_nm, _sx)
    conn.sendall(pack(20, seq, build_20_ack(...)))
    conn.sendall(pack(113, 0, CREATE_PUSH_113))
    conn.sendall(pack(117, 0, CREATE_PUSH_117))
    continue
```

## 七、新号不该有的东西：称号与宠物（2026-11-24 13:20~13:45 修复）

### 现象

新建的 Lv1 角色一进场景，**头顶挂着「神界新丁」称号，身边还跟一只「功夫熊猫」**。
用户质疑：「新注册应该没有职业，为什么这个又有称号又有宠物」。

### 先确认真服基准

MuMu 上账号 `954259122`（刚建完角的那只）实测：

| 项目 | 真服新号 |
|---|---|
| 头顶称号 | **没有**（只有名字「夏侯健远」） |
| 跟随宠物 | **没有** |
| 左上角小熊猫 | 有，但那是**宠物入口图标**，不是宠物实体 |

所以这两样确实是本地服多发的。

### 两个根因

**1. 称号 = `87 -> 88` 这一包（成就/称号列表）**

`88` 是变长的：`d0 88 00 07` + 14×`00` + **1 字节 varint 占位**。

| 状态 | 样本 | 长度 |
|---|---|---|
| 一个成就都没有（真服新号） | `...00 00` | 19B |
| 有成就（主号） | `... cd 0b 7c` / `cd 1c 20` | 21B |

以前不分等级，一律把主号那份 21B 甩给所有人 → 新建号头顶就有称号。

称号表里的对应项：

```
<item title_id="1019" class="1" achievement_name="神界新丁" degree="3"
      title_describe="角色等级达到5级" task="30,5,1" ... />
```

即 **Lv5 才该有「神界新丁」**。现已改成 `build_88()`：`level >= 5` 才带尾巴。

**2. 宠物 = `956 -> 957`**

登录初始化里有一条硬编码补包：

```
956 -> 957 (82B, 内含 UTF-8 "功夫熊猫" e5 8a 9f e5 a4 ab e7 86 8a e7 8c ab)
```

那是**主号（有宠物）**抓到的现场。真服新号 `12:39:34` 发了 `956`，服务端**什么都没回**。

现在 `Player` 新增 `pets` 字段（默认 `[]`），命中规则：

| 情况 | 处理 |
|---|---|
| 存档里有 `pets` | 按存档 |
| 老存档 + 主号 `1784366` | 补种真服已有的三只形象（保持现状） |
| 其余账号 | 空表 |

`956` 时 `pets` 为空 → **不发 957**，只打一行 `跳过 cmd=957`。
`961` 拉宠物栏时按真实数量生成：0 只 → 4B `00 00 04 03`，3 只 → 22B。

### 关于「有职业」

`Class.xml` 里 `id="6" name="新手"`——**6 就是「新手/未转职」这个合法职业**，
真服建角应答 `cmd=20` 里的职业字节也是 `06`。所以新号显示职业 6 是对的，不是错。

## 八、"一升级就变成转过职业的样子"（2026-11-24 14:00~14:20 修复）

### 现象

新建角色（性别男、职业 6 新手）做完第一个任务升到 Lv4，
**模型突然变成女性/职业皮肤**，玩家质疑"怎么一升级又变成转过职业的了"。

### 根因：17 / 28 包头三个字节的语义记错了

旧代码与旧笔记都写成：

```
b[16] = 职业      ← 错
b[18] = 等级
```

真实结构（两份真服样本对齐）是：

| 位置 | 含义 | 真服新号 28（64B） | 真服主号 28（84B） | 真服主号 17 |
|---|---|---|---|---|
| 头长 | `1 + sfield(账号) + sfield(昵称)` | 24 | 16 | 16 |
| rel0 | **性别** 1男/0女 | `01` | `01` | `01` |
| rel1 | **职业** | `06`（新手） | `01`（御剑） | `01` |
| rel2 | **等级** | `01` | `24`=36 | `0a`=10 |

原始 hex 对照：

```
新号 954259122「夏侯健远」Lv1  msj 28:
0c a9"954259122" ac"夏侯健远" 01 06 01 30 1f 00 65 10 07 …
主号 1784366「萌新」Lv36       msj 28:
0c a7"1784366" a6"萌新" 01 01 24 cd 06 73 cd 05 a3 …
主号 17:
0c a7"1784366" a6"萌新" 01 01 0a 00 cc d2 …
```

所以我们一直在**用职业覆盖性别位**，而职业位（rel1）保留模板里的旧值：

- 17 模板（152B）rel1 = `06` → 新号看着像新手，蒙对了；
- 28 模板（73B，早期主号抓包）rel1 = `01` → **一收到 28 就变成御剑**。

升级（交任务）→ `add_reward` → 推 29 / **28** / 30 / 178 → 客户端按 28 重刷角色 → 变职业。

### 修复

`build_17()` 与 `build_28()` 同改成：

```python
_sex_b = 1 if int(cur().sex or 1) == 1 else 0
b[at(16)] = _sex_b        # 性别
b[at(17)] = cur().cls     # 职业
b[at(18)] = cur().level   # 等级
```

主号 `sex=1 / cls=1` 时与旧行为完全一致（三个字节都是 1），所以主号不受影响；
只有"未转职/女号"才会体现差别 —— 正是出问题的那类号。

### 顺手修掉的：战斗里名字还叫「萌新」

`battle.build_open()` 的头部整段抄 `OPEN_TMPL`：

```
01 0c 06 a6 "萌新" 01 00 4c 4c 2f 2f …
        ^^^^^^^^^^ 这里就是玩家昵称
```

新建角色进战斗，左边单位名一直是「萌新」。已加 `name=` 参数动态拼，
`name="萌新"` 时与原模板**逐字节一致**，昵称变长则整包自动变长（客户端按 sfield 解析，安全）。
