1. **形象 id 就是 Pet.xml 的 item id**（`10000`~`10046`），不是自造的 800xxx

3. **美人鱼形象卡（item 20962）→ 形象 id `10017`**（本次实测，唯一强证据）。

## 二、协议时序（182 使用）

客户端：`C->S cmd=182 seq=114 len=2 hex=3101`
- `31` = 背包槽号 **0x31 = 49**（不是十进制 31！178 里最后一格就是 49）
- `01` = 用 1 个（`00` = 全部用完，沿用既有语义）

服务端（真服，一条不差、按这个顺序）：

| 顺序 | 包 | 大小 | 说明 |
|---|---|---|---|
| 1 | `182` 空 ACK | 0B | |
| 2 | `29` | 51B | 属性重算（气血 +1000 后） |
| 3 | `28` | 86B | 面板，idx31 战力 2754→**2774** |
| 4 | `30` | 96B | 装备栏（本例 11 实槽 + 坐骑，96B） |
| 5 | **`947`** | 116B | **宠物详情：形象 id 换成新值（唯一的外观通知包）** |
| 6 | `178` | 345B | 背包全量（50 条 → 49 条，20962 消失） |
| 7 | `306` | 42B | 货币 |

**没有 962 / 957 / 963 推送**：形象卡只改「当前展示宠物的形象」，不新增宠物位。

## 三、947 里哪个字段是形象 id

对同一只宠物（功夫熊猫 Lv19）使用前后逐字节 diff，**只有 3 个字节位置变**：

```
off 23  cd 0a 39 (2617)  ->  cd 0e 23 (3619)   +1002   宠物气血（描述写 +1000）
off 36  cd 03 57 ( 855)  ->  cd 03 6b ( 875)   +20     宠物战力
off 48  cd 27 10 (10000) ->  cd 27 21 (10017)  +17      ★ 形象 id（Pet.xml id）
```

- `off48` 在模板里就是 `cd 27 10 08` 这段（`pack_947` 现在拿它当**静态锚点**，
  切 head/tail 用），所以本地要改成动态写。
- 名字字段（`0xac` + "功夫熊猫"）**不变**：换形象只换模型，宠物名照旧
  （地图上跟随的模型已是美人鱼，飘字仍是「功夫熊猫」）。
- 气血 +1002 而不是 +1000：多出的 2 点应是从「气血上限/成长」派生，非关键。

## 五、本地服落地要点

1. `Player.pet_skin = [10000]`（默认功夫熊猫），必须进 `__slots__` 并落盘。
2. `pet_proto.pack_947(strap, skin=10000)`：把 head 里 `cd 27 10` 换成 `skin` 的变长编码，
   后面的 `08` 保留；`skin != 10000` 时宠物气血那格 +1000（近似真服 +1002）。
3. `182` 分支：`item_kind1=11 & item_kind2=34` 且有映射 → 设 `pet_skin`、消耗道具、
   `follow = [29, 28, 30, 947, 178, 306]`；没映射（赤炎/紫炎冥龙）→ 不消耗、回提示。
4. `WHY_BY_KIND2[34]`（"宠物形象系统尚未实现"）要删掉，否则永远走不到新分支。

     1346(49B) | 1362(37B) | 1363(12B) | 1369(2B) | 178(345B) | 306(42B)

1. **30 包尾部的坐骑块换 id**：`…0000 0000 cd2733 0d 01 01` → `…0000 0000 cd2746 0d 01 01`
   （10035 筋斗云 → 10054 年年有鱼；槽字节恒 `0d`）。坐骑块仍是 6B，长度不变。
2. **1346（坐骑面板）结构**（对比解锁态 40B 与换形象后 49B）：

   ```
   01 | 00000000 | 当前形象id | 坐骑战力 | 状态(01下马/02上马) | 06 | 拥有数量n | [id ff]×n
   32 32 32 32 32 32 | 46 46 46 46 46 46 | [属性块]
   ```
   - 换形象前：`01 00000000 cd2733 05 02 06 01 cd2733 ff 3232… 4646… 06 0a 05 02 03 02 0c 14 0a 04 06 04`
   - 换形象后：`01 00000000 cd2746 cca3 02 06 02 cd2733 ff cd2746 ff 3232… 4646… ccce cc96 cd016d 26 3b 26 0c 14 0a 04 06 04`
   - 第 4 个字段（05 → 163）差值正好 = 战力涨幅 158，应是「坐骑战力」；
     属性块 6 个数 `6,10,5,2,3,2` → `206,150,365,38,59,38`，与形象卡描述逐项对得上：
     攻击 +200、气血 +140、防御 +360、暴击 +36、精神 +56、命中 +36
     → **属性块顺序 = [攻击, 气血, 防御, 暴击, 精神, 命中]**，后 6 个（12,20,10,4,6,4）两档相同，是常量。

   **1369** = `0000`。

## 962 新样本：46B / 7 个形象（2026-11-28 01:06，线上服宠物界面）

打开宠物界面时的完整流程（连点三次都一样）：

```text
C->S 961  len=0
C->S 946  len=1  01        ×3
C->S 973  len=3  01 00 00
S->C 962  len=46  03 [804201,00] [814201,02] [808201,00]
                  04 [810101,00] [812101,01] [803201,02] [815201,00]
                  04 03
S->C 947  len=121 ×3
S->C 973  len=1   01
```

按 `[n1][n1×(uid,尾字节)][n2][n2×(uid,尾字节)][04][余]` 解析**完全对得上**：

| 段 | n | 形象 uid | 尾字节 |
|---|---:|---|---|
| 1 | 3 | 804201(形象4) / 814201(形象14) / 808201(形象8) | 00 / 02 / 00 |
| 2 | 4 | 810101(形象10) / 812101(形象12) / 803201(形象3) / 815201(形象15) | 00 / 01 / 02 / 00 |

两个和旧记录不一致、要改 `pack_962()` 的细节：

1. **uid 后面的那个字节不再是恒 00**：旧样本（4/10/22/28/34/40B）全是 00，这份出现 00/01/02。含义未定（星级/状态/序号？），但**不能写死 0**。
2. **尾部**：n1=3 时真服发的是 `04 03`，而 `pack_962()` 现在按 `3 - n1` 算，会发 `04 00`。说明尾巴那个数字不是「3 - 已领取数」。
