# 打怪闪退（151 开战包）—— 变长整数编码写错

2026-11-24 16:3x 定位并修复。

## 1. 现象

打「心魔 Lv.5」(111301) 时客户端闪退。特征：

- 服务端日志 `-> cmd=145 ACK + 151` 之后立刻 `对端关闭（回放指针 1/42）`
- 客户端 logcat：`got packet, seq = 0, cmd = 151` 后 **55ms 进程消失**
- **没有 Fatal signal、没有 tombstone、没有 backtrace** → 不是 native 崩溃，是客户端**自检失败主动 exit**
- 打「仙界守卫 Lv.1」(111101) 偶尔能打，所以不是必现

## 2. 定位过程

用「发真服原包」做对照，一次把范围缩到 151：

| 发的内容 | 结果 |
|---|---|
| 真服 15:34:43 打 111301 原包（35B，`68 68 3f 3f … 5a 5a`） | **不崩**，正常打完 |
| 本地动态 151（39B，`cc f4 cc f4 cc 8f cc 8f …` 之前是 `cd 00 f4`） | 崩 |

两者结构完全同构，差别只在数值编码。

## 3. 根因：`enc_val()` 的分档阈值写错

`battle.py` 里的协议变长整数，原来写的是：

```python
if v < 0xCD:      # 205
    return bytes([v])          # 单字节
if v < 0x10000:
    return b"\xCD" + u16       # 三字节
```

**真服的规则是三档，128~255 必须用 `0xCC` + 1 字节**：

| 值 | 真服样本 | 长度 |
|---|---|---|
| 63 | `3f` | 1B |
| 76 | `4c` | 1B |
| 104 | `68` | 1B |
| **132** | **`cc 84`** | **2B** |
| 1067 | `cd 04 2b` | 3B |

按老代码，132 会发成单字节 `84`，244 会发成 `cd 00 f4`。客户端按有符号字节解析 `84`（= -124），校验不过就 `exit()`。

**为什么仙界守卫能打**：Lv8 之前玩家血 132、怪血 80 都在 128 以下，全走单字节，恰好蒙对；一到 Lv11（血 350 / 蓝 268）或者血量跨过 128 就必崩。

## 4. 修复

```python
def enc_val(v):
    v = int(v)
    if v < 0x80:
        return bytes([v])
    if v < 0x100:
        return b"\xCC" + bytes([v])
    if v < 0x10000:
        return b"\xCD" + v.to_bytes(2, "big")
    return b"\xCE" + v.to_bytes(4, "big")
```

现在三档与真服样本逐字节一致：

```
   63 -> 3f            132 -> cc 84
   76 -> 4c            143 -> cc 8f
  104 -> 68            244 -> cc f4
 1067 -> cd 04 2b
```

## 5. 顺带修的两处

1. **151 里的怪物血量必须是 `Monster.xml` 的 `hp_max`**，不能再按「回合数折算」发假血
   （以前 `max_hp = CLIENT_PDMG * 回合数`，打 111101 时折算刚好 80 蒙对，打 111301 折算成 32 而配置 90）。
   现在 `max_hp = cfg_hp`，`hp` 按回合进度等比缩放，血条比例仍然正确。
2. **151 里的昵称按「完整字符」截到 ≤6 字节**。真服所有十档样本的昵称都是 6 字节「萌新」；
   之前先切字节再删续字节，会把「门」切成 `e9`，产生非法 UTF-8。

- 只要 `enc_val` 改动，必须同时核对 `151`、`148`、`149` 里的所有变长字段
- 判断「是不是 151 的问题」：看有没有 **Fatal signal**。有 → native；没有、55ms 就干净退出 → 协议自检，优先查 151
- 真服三档样本（35B/37B/39B）都在 `logs/relay.log`，任何可疑改动先跟它逐字节比
