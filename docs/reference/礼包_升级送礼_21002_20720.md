## 3. ★ 分配规则：先扣格位，再发掉落

第 1 包是判定这条规则的关键：

- 开之前空位 `1 / 49 / 52`，格5 是 `15级妖灵礼包`。
- 掉落顺序：妖丹(叠)、觉醒(叠)、经验丹→最小空位 **1**、鲜花礼包→**格5**。
- 若「先加掉落后扣格位」，格5 当时还被占着，鲜花礼包只能进 **49**。
- 真服落在 **5** ⇒ **格位先被清空，掉落才入包**，新掉落按「可叠先叠、否则最小空格」找位。

本地 `local_server3.py` 的 182 尾巴原来是「先发掉落后扣格位」，礼包会整整差一格。
已改为礼包分支内先扣（`pre_taken = True`），尾部 `if not pre_taken:` 兜住其它分支。

## 5. `113` 的两发：`66` 子类型，暂未解

```
17:28:02  S->C 113 len=11 hex=6601ce000dbba115000000
17:28:40  S->C 113 len=11 hex=6601ce000dbba22a010000
```

- `113` 是「对象列表」总命令，子类型由首字节区分（`65` 场景怪、`66` …）。
- `66 01` = 1 条：`id varint(ce 000dbba1=900001)` + `15` + `000000`；
  第二次变成 `id 900002` + `2a(=42)` + `01 0000`。
- 时间点分别是「打开升级送礼面板」和「开完 30级紫精礼包」之后，判断是**活动/礼包档位的领取状态**，
  但字段含义没有第二组样本佐证，**不下结论**，本地也不发。

## 7. 真服自己也用不了这张称号卡（玩家实测）

玩家在线上服点背包里的 `30060`「仙法小成」——**没反应 / 用不了**。对照：该号 17:17 就已经
戴过 1020「仙法小成」，17:20 卸下、17:23 换回 1019。也就是说**称号的获得路径不是这张卡**，
卡在这里只是「礼包里塞的一件展示品」，对方服务端对 `182` 根本没实现（或是漏了）。

本地处理：`30060` 可用（Lv≥30 → `cur().title = 1020`）。这是**故意超集**：
比真服多一条能走通的路，不会让玩家卡住。要对齐真服只需把 `TITLE_CARD` 里的 `30060` 摘掉，
它就会落到「称号系统未实现，道具已保留」。
