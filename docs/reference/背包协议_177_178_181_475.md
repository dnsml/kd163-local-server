## 整理（181）行为

- 客户端点「整理」只发 `181`（len=0）。服务端职责：**把背包按序重排、格位从 0 连续
  重编号，再把同号 181 全量回过去**；客户端拿到就按新顺序重画，没有单独的「排序结果包」。
- 真服 01:43:52~56 连点 4 次，回包内容与顺序完全一致（**幂等**，不是洗牌）。
- 本地 2026-11-28 16:30 前是「原样返回存档顺序」→ 玩家点整理看到的就是完全没反应。

### 排序键（从真服 178 的 52 件逐条解出来的）

大类型（`item_kind1`）顺序：**3 消耗 → 6 材料 → 7 → 9 宝石 → 10 药品 → 11 宠物 →
12 强化 → 13 藏宝图 → 1 装备（整体排最后）**；同一大类型内按 `kind2` 升序、再按
物品 id 升序；同 id 多堆不合并，按数量降序。

## 476 = 排行榜

```text
[05] 5 个玩家
每个： [名字长度?][名字 UTF-8][...] + 一长串 装备/时装/翅膀 id
```

能解出的名字：一剑破九州 / 茉莉 / 幸运 / 林风芳 / 棉花糖，每人后面跟着
`11235/11529…`、`10041/10050/10059/10062`（时装、翅膀）、`160005`（真龙魂）等 id，
所以是**装备/战力排行榜**，不是背包。`seq=0`，同一时段重复请求内容完全一致。

本地暂无 476 模板，475 落到「无模板静默丢弃」，排行榜面板留空，不影响其它功能。
