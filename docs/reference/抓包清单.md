## 一、为什么能「举一反三」——有硬证据

抓包里所有列表型应答都是同一个形状：**一个包头 + 定长条目 × n**。

```
cmd=306  技能列表   02 | cdeac5 0000000000 | cdeb29 0000000000 | 00
                     ↑2条  ↑60101 仙人指路  ↑60137
cmd=178  某列表     400300 | cd4ede 00010a01 | cd4fd0 00010102 | cd5209 00010101
                            ↑条目1           ↑条目2           ↑条目3
cmd=1154 某配置     15 | 01000000 02000000 ... 11000000
                        ↑ 17 个 int32，值 1..17
```

**条目是定长的，数量可变。**

注意 306 的首字节正好是条数（2），但 178（`40 03 00`）和 1154（`15`）不是——
所以别指望「首字节一定是数量」。每个 cmd 的包头单独确认一次，确认完就永久有效。

但这不影响结论：**条目从 1 条变 100 条，结构不变。** 抓 2~3 条就够，
剩下的让代码循环——590 个任务、几百件装备，都是同一张表填出来的。

再加一条：`1154` 在 14:49 和 15:28 两次登录（都是同一个号）内容**一字节不差**，
说明这类是账号无关的静态配置表，抓一次永久可用。

## 二、另一个关键事实：大部分操作「不带参数」

扫了一遍 77 个请求，绝大多数是 **0 字节**：

```
87 → 88      空请求   → 21B 应答
177 → 178    空请求   → 23B 应答（3 条目）
305 → 306    空请求   → 18B 应答（2 技能）
529 → 530    空请求   → 4B
657 → 658    空请求   → 11B
1154         空请求   → 69B（17 个 int32）
2113 → 2114  空请求   → 50B
```

**点一下按钮 = 发一个空包 = 服务端回这个面板的全部数据。**

所以抓包不是「猜参数」，是「点按钮 + 记下我点了什么」。你点完告诉我功能名，我就能把 cmd 号贴上标签，这个面板就算拿下了。

**所以「举一反三」不是省事技巧，而是唯一需要做的事**：内容客户端自己有，
服务端只负责「你这个号现在是什么状态」。抓的是**状态包的结构**，不是数据本身。

- **每个具体任务**：结构一样，只换 ID
- **不同等级的同种操作**：服务端只算数值，包结构不变
- **重复的同类面板**：抓 1 条就够，多抓只是确认

## 六、操作铁律（影响我能不能解析）

1. **每点一个按钮，停 2 秒**。连着点，请求和应答会串在一起分不清。
2. **同一种操作做 2 次，但对象不同**（比如打两只不同的怪）。两个样本一对比，我就能自动标出哪个字节是 ID。
3. **别开自动战斗**。自动战斗会在 1 秒内刷十个 `146`，全是噪音。
4. **别关奖励/获得物品弹窗**，先让我抓。
5. 点完一批，跟我说一句「点了 XX」，我立刻按时间切段解析。
