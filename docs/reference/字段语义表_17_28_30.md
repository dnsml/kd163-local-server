## 0. 证据等级

表里「等级」一列只有三种值，别看混：

| 等级 | 含义 | 判定方式 |
|---|---|---|
| **实证** | 改这个值 → 客户端对应 UI 必变；或真服两份不同样本 + 29 交叉恒等 | 至少两种独立证据 |
| **定位** | 字节位置、宽度、是否定长已确定，语义只有间接证据 | 只能保证「别动它不会坏」 |
| **未定** | 只知道占几个字节，语义完全不明 | 一律原样透传 |

> 客户端的类名/结构体名没有做符号级还原（APK 未反编译到字段名），
> 表里的字段名是**按线上行为命名的功能名**，等价于客户端解析顺序。
> 需要真实类名时再单独做 dex 符号分析，不影响改包。

## 1. 公共编码（三张包共用）

### 1.1 帧头

```
u16 BE 总长(含 6B 头) | u16 BE cmd | u32 BE seq | payload
```

### 1.2 payload 只有两种东西

| 类型 | 编码 | 长度 |
|---|---|---|
| 短字符串 | `0xA0 \| len` + UTF-8 字节（len ≤ 0x1F） | 1 + len |
| 整数 | `<0x80` 裸单字节 / `0xCC`+1B / `0xCD`+2B / `0xCE`+4B | 1 / 2 / 3 / 5 |

**没有长度前缀、没有类型标记**，纯靠首字节判断。所以：

- 同一个字段，值 127 → 1 字节，128 → 3 字节，**后面所有字段整体位移**。
- 这就是为什么 28 必须 `tokenize → 改值 → render`，绝不能按固定偏移写。
- 而 17 的装备段必须**定长**，所以改 17 时只改「值」，宽度保持模板原样（见 2.4）。

### 1.3 token 下标 ≠ 字节偏移

`grant.tokenize()` 把字符串也当成一个 token。所以：

```
idx = 第几个「值」（字符串算 1 个）
off = 这个值在 payload 里的字节起点
```

账号/昵称一变长，`idx` 不变、`off` 全变。**改包按 idx，校验按 off + shift。**

`shift = (账号字段长 - 8) + (昵称字段长 - 7)`

主号 `1784366` + `萌新` → `shift = 0`，本文所有 off 都是 shift=0 的值。

## 2. cmd 17 —— 登录角色快照

### 2.1 为什么它最容易出事

客户端登录后**先照 17 建人、建地图、挂称号、记货币**，然后才收到 28/29/30。
所以 17 里任何一个「抓包那个号的值」没改，都会在客户端先落一次账：

- 货币旧值 → 收到 28 真值后按差额弹「绑定铜币 -2,2xx,xxx」
- 称号旧值 → 登录自带「神界新丁」，第一次交任务收到 88 就被换掉
- 场景旧值 → 地图上同时出现两个场景的怪
- 装备旧值 → 模型穿的是抓包号的装备

**一句话：17 里凡是「跟着角色走」的字段，全部要动态写。**

### 2.4 硬约束（改 17 只有这四条）

1. **定长写**：货币/称号/等级/经验/场景/坐标全部按模板原宽度覆盖字节，
   **不能 token 重编码**。装备段是 6B 步进，一旦前面缩短 2B，后面全错位。
2. **装备槽不许改槽号**：`[id3B][槽号][01][01]` 的槽号与 `01 01` 保持模板值，只换 id。
   空槽也写 `CD 0000 + 原槽号 + 01 01`（6B），**不能整项写 0** —— 槽号 0 会让客户端越界崩溃。
3. **武器槽字节固定 `07`**（与 30 不同，30 跟武器 id 走）。
4. **称号没有就写 `CD 0000`**（3B），不要删掉这 3 个字节。

### 2.5 两个长度变体

| 样本 | 长度 | 差异 |
|---|---|---|
| `TPL17_LIVE`（主号 Lv10） | 197B | 本文基准 |
| 真服新号 `954259122` Lv1（`relay.log` 17:19:53） | 162B | 账号 10 字/昵称 13 字，但经验 0、场景 101、阅历 0 都是 1 字节，所以反而更短 |

**字段顺序完全一致**，只是 varint 宽度不同：
`性别/职业/等级 → 当前血 → 当前蓝 → 经验 → 场景 → X → Y → 阅历 → 0,0,0,5,0 → 货币…`

> 服务端只用 197B 模板，所以表里的 off 稳定可用。
> 若哪天真服换成 162B 变体，用 `work/probe_semantics.py real` 重跑一次即可定位。

```

```

| 状态 | N | 坐骑 | 长度 | 真服样本 |
|---|---|---|---|---|
| 全脱 | 0 | 无 | 68 | — |
| 全脱 + 坐骑 | 0 | 有 | 74 | 00:45:20 |
| 6 件防具 | 6 | 无 | 80 | 20:46:30 |

| 7 件 + 坐骑 | 7 | 有 | 88 | — |
| 11 件全满 + 坐骑 | 11 | 有 | 96 | 02:32:37 |

反推：`N = (L - 68 - 6*hasMount) / 2`。

### 4.4 尾部两块是定长

- **翅膀块固定 20B**：`CE`+u32 形象 ID + 15×`00`；没翅膀就 20×`00`。
- **坐骑块 6B，但只在真有坐骑时存在**：`CD`+u16 id + `0D 01 01`。
  **没坐骑千万不要补 6 个 0** —— 多 6B 会被客户端判成「整包长度不对」直接丢弃，
  表现是「模型穿着整套装备、面板 11 格全空」（2026-11-26 14:0x 事故）。
