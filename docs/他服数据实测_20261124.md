## 2. 首任务链（逐包实录）

### 2.1 点 NPC 九天玄女

```
C->S cmd=116 len=1 hex=00
S->C cmd=1   len=29 hex=04bbe69cac...e883bd   →  "本服就未恢复此功能"
```

**关键：他服的 `116`（点击目标 / 自动寻路）是被禁用的**，点 NPC、点地面、点怪一律回这句 29 字节提示。
也就是说在他服**点怪物不会自动走过去**，只能自己拖摇杆走到怪身边，才能触发 `145`。

> 本地服目前也是回同一句（`builtin_resp` 里 116 分支）。
> 结论：本地服"点怪不动"不是 bug，是跟他对齐的；但玩家体验上确实需要能寻路。

### 2.2 接 400101「重归仙界」

```
C->S cmd=211 seq=375 hex=ce00061ae5          # 任务 400101
S->C cmd=211 seq=375 len=7 hex=ce00061ae50101
```

对话文本：
> 夏侯健远，十六年了，你终于重返仙界了。
> 任务奖励：经验 800　绑定铜钱 200

**应答 7 字节**：`[ce 任务id] [01] [01]`，尾两字节 `01 01` = 接了即满足条件（对话任务）。

### 2.3 交 400101 → 完整推送包序

```
C->S cmd=214 seq=380 len=5 hex=ce00061ae5
S->C cmd=214 seq=380 len=0                                     # 空回执
S->C cmd=29  seq=0   len=27 hex=4c2f0b11001f011e000528...ccf052  # 属性刷新
S->C cmd=28  seq=0   len=66 hex=14a939...cd0320                  # 角色信息（经验/绑铜/等级）
S->C cmd=210 seq=0   len=8  hex=0001ce00061b4901                 # 下一环 400201 进行中
```

- **没有独立的"奖励"包**：800 经验 / 200 绑铜直接体现在 `28` 的数值里。
- 交完立刻 **Lv1 → Lv2**，经验条 5.00%（说明 Lv1 升 Lv2 只需 800 经验，正好被首任务一次带过）。
- `210` 结构：`00 01 [ce 下一环id] 01`，与本地服 8 字节实现一致。

### 3.3 数值量级差异（本段最重要的发现）

| 对象 | 他服实测 | `Levelup.xml` 原值 | 倍率 |
|---|---:|---:|---:|
| 玩家 Lv2 血 | 5465 | 76 | 71.9× |
| 玩家 Lv2 蓝 | 1443 | 47 | 30.7× |
| 怪物（绿豆鲨 Lv30）血 | 30720 | 查 Monster.xml | — |
| 单回合伤害字段 | 30111 / 6400 等 | — | — |

他服那个 Lv2 号的 5465 血 / 1443 蓝**不是配置真值**，是私服给的开局加成（出生送属性）。
所以它的血条基数大、单回合掉血看着比例小但"合理"，战斗要打 20~30 秒。

## 4. 结论

1. **任务链完全对得上**：400101（800/200，`0101`）→ 400201（900/500，`0001`）→ 400301 采集。本地服无需改动。
2. **`116` 在他服也是"未恢复"**：点怪不自动寻路，这是他服现状，不是我们独有的缺陷。想做好体验，需要实现 116 寻路（目前缺真服成功样本）。
3. **他服是靠"放大属性"让战斗看起来正常的**：Lv2 就 5465 血，怪 30720 血，同一量级，血条比例自然对。
   本地服走的是原版配置（Lv2 76 血 / 怪 80~1939 血），客户端按小数值算伤害（8~16），
   一旦遇到 1939 血的怪，服务端 5 回合就结算，客户端血条只掉一小截 → **"莫名其妙胜利"**。
4. **修血条的正解有两条**：
   - a) 把 `151` 的玩家血量与怪血量同倍率放大（例如 ×70），让客户端算出的伤害同步变大；
   - b) 让服务端回合数 = 客户端伤害下怪血能撑的回合数（`151` 怪血 = 客户端每回合伤害 × 回合数）。
   两者都需要一次实机对比（改完打同一只怪，看血条是否走空）。
