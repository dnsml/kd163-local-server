# 交接说明（给接手的 AI / 开发者）

一句话：这是《口袋修仙 / 梦幻神界》的自建服务端，协议靠真服抓包逐字节逆出来，纯 Python 标准库实现。
目标是把本地服做到能给真人发账号密码玩通全场（登录→建角→任务→战斗→背包→宠物妖灵→商城）。

## 1. 运行环境

| 项 | 值 |
|---|---|
| 服务端入口 | `local_server3.py <port> <pem> <key>`，默认 9000 |
| 端口分工 | 9000 游戏协议（仅 `/auth` 走 TLS，其余明文）；8080→80 资源 CDN |
| 服务端证书 | 抓包版/公网包用 `patch/exact.pem`（md5 `126de957...`）；开发版包 `com.kd163.dev` 用 `patch/local/exact.pem`（本地材料，不入库）。两者都必须与对应 APK 内嵌的同一张 |
| 本地测试机 | 雷电 `192.168.0.111:5555`；正服/他服在 MuMu `127.0.0.1:7555` |
| 他服地址（观察用） | `124.223.56.189:9000`，经 `capture_proxy.py`（:19000）镜像 |
| 日志 | `logs/server.log`（本地）、`logs/relay.log`（真服/他服完整包序） |

抓包日志格式：`[时间] 方向 cmd=号 seq=号 len=长度 hex=原始字节`。`C->S` 是客户端上行，`S->C` 是服务端下行。
**分析任何行为都以 relay.log 的原始 hex 为准，不要相信任何二手描述。**

## 2. 帧格式

```
pack(cmd, seq, payload) = >HHI(6+len(payload)) + >H(cmd) + >I(seq) + payload
```
`len` 字段含 6 字节头。短字符串 = `0xA0|len + utf8`。变长整数 `enc_val`：
`<0x80` 单字节 / `0x80..0xFF` 用 `cc` / `0x100..0xFFFF` 用 `cd` / 更大用 `ce`+4字节大端。

## 4. 七个致命坑（踩过，别再回退）

1. **未注册 cmd 必须静默丢弃**。回 `cmd=1`（提示包）客户端 30ms 内 SIGABRT，无 Fatal / 无 tombstone。
   例外：登录期客户端主动请求但服务端不实现的 `22/542/663/1125/1134/1384`，**必须**同 seq 回 `cmd=1` 文本，
   否则 `loading m_depth` 归不了零，一直转圈。
2. **`enc_val` 分档错 = 收到 151 后干净退出**。这是「打怪闪退」的真凶，不是血量问题。
3. **`115` 要回两条 `118`**：`06<pos>` + `10<pos>`。不回的话客户端寻路走两步就停，永远发不出 `145`。
4. **`17/28/30` 的 `(性别,职业,等级)` 必须同源**。任一处用旧模板 → 等级乱跳 / 渲染线程段错误。
5. **`947` 不要自己解结构**，按「上阵妖灵集合」查真服原包回放（`res_cfg/pet_tpl.json`），猜结构会崩。
6. **`30` 尾部必须按真服长度写**：翅膀块**有没有翅膀都占 20B**，坐骑块**只有真有坐骑才写 6B**。
   无坐骑时多补 6B → 88B（真服 82B）→ 客户端整包丢弃，表现为「模型穿着整套装备、面板 11 格全空」。
   判定方法：剧情神装 6 防具 + 4 空首饰 + 武器 + 4B + 20B 翅膀 = **82B**，可以用 `work/test_newbie_char.py` 逐字节对比。
7. **`17` 是抓包号的快照模板，头部带旧货币和旧称号**。只动态化装备/等级/场景是不够的：
   `idx18~21` 货币、`idx22` VIP、`idx24` 称号都必须按存档**定宽**写回（不能走 token 重编码，
   否则包长缩短会让后面的定长装备段前移）。不改的话客户端先按 17 记账、再收到 28 真值，
   按差额弹「绑定铜币 -2,xxx,xxx / 元宝 -1749 / 绑定元宝 -4050」，并且登录时天生带一个不属于自己的称号。

## 5. 战斗数值模型（2026-11-27 定稿，改动前务必读）

**当前默认 `BATTLE_HP_TRUE=1`：`151` 直接下 `Monster.xml` 真值血量**，血条按真值一条条掉。

- 一组怪固定 **3 只**：units `7/8/9`，`151` 里的 `03` 是数量，侍从 oid `90000101`/`90000201`，血 = 主怪/3。
- 「客户端每回合固定扣 16（打）/13（挨打）」是**旧模型**。只有显式 `BATTLE_HP_TRUE=0` 才回到
  `max_hp = 16*rounds_to_kill` / `disp_player_hp_max = 13*rounds_to_die` 的折算；
  正常别再开，折算只能用来对照旧行为。
- **`148` 的伤害是负数补码，且只能取一次负**：`-16~-1` → `0xF0|(16+v)`（`f7` = -9）、
  `-128~127` → `d0` + 1B、其余 → `d1` + u16（`d1feae` = -338）。
  内层再取一次负会写成正数 → 客户端当成**回血**。
- **逐行动者结算**（不是「先算完再补」）：`turn_order()` 按敏捷降序
  （怪 = `40+4*(lv-1)`，`Levelup.agile` 恒 40 不可用，侍从 ×0.8；玩家取 `29` 面板 agile），
  逐个「判活 → 扣血 → 立即判胜负」；玩家死立刻 `lose`，怪全死立刻 `win`，不再补刀。
  `148` 的条目顺序用实际出手序列 `done`，不是静态 `turn_order()` 结果。
  另外**不能按 payload 去重**：普通攻击每回合 `146` 都是 `01 07 cd 27 d9`，去重会吞掉第二回合。
- **单体/群体看技能**：`146` = `[动作][目标uid][CC/CD/CE+技能号]`，查 `res_cfg/Skill.xml`（2129 条）。
  `target_type=5` 是群体（`10201` 九天剑阵、`10211` 万剑归宗…），对每只活着的各写一条；
  其余单体只打 `payload[1]`；宠物只打当前选中的那只。
- **技能倍率**：`damage_percent` 直接乘进伤害（`d = round(deal * damage_percent)`），
  不再只当「有没有这个技能」用。
- **宠物伤害**：`PET_DMG=338` 是 **Lv12** 宠物的真服值（`947` 模板第 14 字节 `0x0c`），
  按 `PET_DMG_REF_LV=12` / `PET_DMG_GROWTH=0.12` 缩放（Lv20≈662，对上真服 `-642`）。
  按 Lv1 锚定会把 Lv12 放大成 784（2026-11-27 20:37 玄蜂实测踩过）。
- 伤害口径一律用 `panel_attr()`（与 `cmd=29` 同源，含装备/强化/套装/妖灵），**不要**乘等级假系数。
- 防御 `action=4`：玩家不出手、宠物只表演不掉血、受伤减半
  （`PET_ATK_SHARE=0` / `DEF_TAKE_SHARE=0.5`）；纯防御打不死怪，`MAX_ROUNDS=20` 力竭判负
  （真值模式下限放宽到 `BATTLE_MAX_ROUNDS`，默认 60）。

## 8. 推代码到 GitHub

`origin = https://github.com/dnsml/kd163-local-server`，分支 `master`。

**首选：直接跑脚本，不需要梯子**

```bash
bash work/gh_push.sh            # 起隧道 → push → 校验 remote sha 与本地一致
```

原理（2026-11-27 实测）：关掉梯子后 `github.com` **域名**直连是 TCP 超时，
但 GitHub 真实 IP（`140.82.113.4`、`20.205.243.166`、`20.27.177.113`…）443 全部 OPEN，
`curl --resolve github.com:443:140.82.113.4` 访问 `git-receive-pack` 返回 **200**。
所以故障只在「域名这一步」，TLS 和鉴权都是好的。
`work/gh_tunnel.py` 是个本机 CONNECT 代理，收到 `CONNECT github.com:443` 就按 IP 池
建立上游连接，git 侧 TLS 的 SNI 仍是 `github.com`，证书校验不受影响。

```bash
# 等价的手工写法（隧道另开一个窗口）
python work/gh_tunnel.py 7899
git -c http.proxy=http://127.0.0.1:7899 -c http.sslBackend=openssl push origin master
```

有梯子时可以直接用回旧通道（仓库里已固化 `http.proxy=127.0.0.1:7890`）：

```bash
git push origin master
KD_GH_PROXY=http://127.0.0.1:7890 bash work/gh_push.sh
```

注意两点：

- **schannel 后端经代理必定握手失败**（`SSL/TLS connection failed`），必须 `http.sslBackend=openssl`；
  这是当初误判「443 完全不通」的原因。
- 认证用 `D:/66666/.gh_pat`（PAT，scope 只有 `repo`）；`gh_push.sh` 会自动用它，
  不依赖 GCM 弹窗（关梯子时窗口也弹不出来）。该 PAT **没有** `admin:public_key`，
  所以加不了 SSH 公钥，SSH 通道（`ssh.github.com:443`）目前只能连上、认证不过。

> ⚠️ **不要再用 `work/gh_api_push.py` 推**。它走 REST API 逐条 replay，
> 生成的 commit 是**新对象**（作者变成 token 账号），哈希全变；
> 结果是本地和远程成为两条平行历史，只能强推。2026-11-27 就是这么撞上的：
> 本地 `2e59811` 与远程 `727666f` 标题相同、树对象完全一致、哈希不同。
> 远程旧链已备份为分支 `backup-remote-20261127`。

> 若 `git status` 显示 `## master...origin/master [gone]`：这台机器上
> `.git/refs/remotes/origin/` 里的文件会被反复清掉（fetch 报 `[new branch]` 也没留下）。
> 修法：`git fetch origin` 之后手工补引用，内容就是远端 sha + 换行
> `printf '<sha>\n' > .git/refs/remotes/origin/master`。
