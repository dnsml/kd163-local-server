## 十七、强化成功率 / 失败掉级 / 战力（2026-11-23 01:1x）

### 17.1 用户实证的三条规则

> 「强化好像有强化成功的几率 失败会掉一级 但是掉到 3 6 9 是不掉的。
>  还有强化成功会加属性 也就是所谓的战力值。」

服务端现在按这个实现，客户端只负责显示成功率，判定全在本地服。

### 17.2 成功率

```python
BASE_RATE = {0:100, 1:95, 2:90, 3:85, 4:80, 5:75,
             6:70,  7:65, 8:60, 9:55, 10:50, 11:45}
实际成功率 = min(100, BASE_RATE[当前等级] + 强化石加成)
强化石加成：初级 5% / 中级 8% / 高级 12% / 特级 15%（Item.xml 原值）
```

`+0 → +1` 恒 100%（加石头后），所以新装备第一下不会失手；
`+3 之后`才开始明显掉档，和用户描述的体感一致。

> 注意：这套**基础值是按真服「18:30 连做 18 次 +1~+3 全成功」反推的，
> 不是从服务端包里读出来的**（客户端配置里没有成功率表）。
> 想精确校准，需要在真服 +7 以上故意失败几次并抓包。

### 17.4 战力（cmd=29）动态化

真服 18:20~18:30 连续 16 次强化的 29 包逐条反推，公式误差 0：

```
战力 = 模板基数 + Σ 已穿装备 strengthen_当前等级[attr53]
```

- `strengthen_N` 是**累计值**不是增量（`strengthen_3` 的 53=70 表示 +3 时总量 70）。
- 验证：11108 +1 → +35、+2 → 再 +18、+3 → 再 +17；11109 +1 → +30、+2 → +15。
- **武器 11114 的强化不含 attr53**（只有 51/52 最小最大攻击），
  所以只强化武器时 29 的 field0 一动不动 —— 真服就是这样，不是 bug。

实现：`build_29()` 从模板包按 varint 拆 26 个字段，只替换 field0，
其余字段沿用登录模板（结构没完全破译，乱写会把属性面板搞崩）。
登录回放、`31` 刷新、交任务、强化后都会走这个动态包，
重登后战力不会被刷回旧值。
