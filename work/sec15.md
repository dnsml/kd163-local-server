## 十五、迷宫入口 + 锻造强化 822 协议还原（2026-11-23 18:40）

### 15.1 迷宫进不去的真实原因

真服抓包（`logs/relay.log` 18:11:23）：

```
C->S cmd=1857  (点迷宫入口)
S->C cmd=1858 len=1 hex=02        (档位列表)
C->S cmd=1859 len=1 hex=01        (选第 1 档)
S->C cmd=1    len=36              (拒绝，文本提示)
```

`cmd=1` 文本解出来是：**「此模式请达到20级后再来」**
（`04da` + u16BE 长度 `0x20` + 32 字节 UTF-8）。

不是看不到按钮，也不是没解锁，就是**等级不够**——当时真服角色 `cmd=28` 解析是 Lv10。

本地服已补：

| cmd | 行为 |
| --- | --- |
| `1857` | 回 `1858 [02]`（档位 1/2 可选） |
| `1859` | `PLAYER_LEVEL < 20` → 回 `cmd=1` 提示；否则标记 `maze_ready` 并回空 |
| `1859` 成功后 | 若当前任务 `task=35`（如 `400802 回梦迷境`）→ 推 `210` 可交并落盘 |

`task=35` 的语义就是「进一次迷宫」，之前本地没有完成出口，所以任务永远进行中。
把角色 GM 提到 Lv20 后，迷宫能进、`400802` 能交，用户已确认「可以了」。

### 15.2 强化 822 载荷结构（真服 18:30 连续 18 次强化反查）

```
C->S cmd=822 len=6 hex=00 0a 01 cd4ead
                        │  │  │  └── 材料 item id（varint，cd4ead = 20141 初级强化灵石）
                        │  │  └───── 消耗数量（01）
                        │  └──────── 材料在 178 列表里的下标（0a）
                        └─────────── 部位码
```

**部位码 → 装备槽不是 1:1，这是之前强化打错槽的根因：**

| 部位码 | 装备槽 | 物品 id（御剑神装） |
| --- | --- | --- |
| `00` | 1 | 11108 |
| `01` | 2 | 11109 |
| `02` | 3 | 11110 |
| `03` | 4 | 11111 |
| `04` | 5 | 11112 |
| `05` | 6 | 11113 |
| `0a` | 7 | 11114 |

材料两种：`cd4eaa` = 20138 初级强化仙玉、`cd4ead` = 20141 初级强化灵石。
本地客户端强化时发的是短包 `05 0b 00`（部位 5 → 槽 6，没带材料段），所以按「无材料段」放过。

### 15.3 强化铜钱消耗公式（实测零误差）

真服每次强化后 `cmd=28` 的 idx18 **绑定铜钱**差额：

| 强化 | 消耗 |
| --- | --- |
| +0 → +1 | 1500 |
| +1 → +2 | 3000 |
| +2 → +3 | 6000 |

即 **`1500 × 2^当前等级`**。账号铜钱=0 时扣的是**绑定铜钱**，
所以实现是「先扣铜钱，不足部分扣绑铜」，两种都不够就回 `cmd=1 「铜钱不足」`。

16 次连续强化的实测差额与公式逐项比对**全部一致**（`work/test_enh.py`）。

### 15.4 强化回包序列

```
S->C 822  空
S->C 178  背包/材料列表（材料数量递减，真服 114B）
S->C 818  len=29，只回被强化的那一槽
S->C 29   属性/战力刷新
S->C 28   角色快照（货币在这里，绑定铜钱已扣）
S->C 30   装备全表（86B，不带强化等级）
```

`818` 布局：`[条数][槽][cd+id 2B][01][00][强化等级][20B 空]`，单条恒 28B，
**强化等级在单条记录 offset 6**（完整包里是 `b[7]`），写入后客户端立刻显示 +N。
`build_818()` 已按此写 `ENHANCE[slot]`，与真服样本逐字节一致。

- 之前 `task=4` 接取后服务端又补推 `210(9B)`，客户端把它当成「又接了一次」→

  **不要再补推 210**。
